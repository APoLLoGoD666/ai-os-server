## RS-02: Constitutional Basis

**Section Title (R0 §4.1):** Constitutional Basis

**Identifier:** RS-02

**Why Reality Representation Requires a Dedicated Runtime**

The constitutional document stack specifies reality but does not operationalize it. D2 defines what a Universal Reality Object (URO) constitutionally is; D3 defines the constitutional structure of the Reality Fabric. Neither specifies how these constructs are maintained at runtime. Without a dedicated runtime, four constitutional failures arise:

**P-FAB-1 — Representation Fragmentation:** Without RT-05, each consuming runtime (RT-08 Observation, RT-09 Knowledge, RT-06 Relationships) would represent reality objects according to its own internal requirements. The same constitutional object would have inconsistent representations across runtimes, violating the D3 constitutional mandate for a unified Reality Fabric.

**P-FAB-2 — Provenance Dissolution:** Constitutional object provenance — the chain from FoundingRatification through each authorized modification — requires a single custodian. Without RT-05, provenance chains fragment across runtimes, making it constitutionally impossible to verify the continuous legitimacy of any reality object.

**P-FAB-3 — Ontology Boundary Erosion:** Without a runtime explicitly constrained to D0/D1 constitutional categories, reality representations would accumulate extra-constitutional categories over time. RT-05's constitutional constraint (RT05-INV-07: representation must not exceed constitutional ontology) requires an enforcement point.

**P-FAB-4 — Gate 2 Fragmentation:** RT-03's Gate 2 (Object State) requires a single authoritative source of object state. Without RT-05 as that single source, Gate 2 would yield inconsistent results depending on which runtime was queried, undermining constitutional enforcement integrity.

RT-05 exists to maintain the constitutional representation of reality through Universal Reality Objects, their relationships, provenance chains, temporal validity markers, and coherence states — constituting the operational Reality Fabric of APEX.

RT-05 is the operational reality substrate of APEX. It transforms the constitutional specification of reality (D2 UROs, D3 fabric) into a living, maintained, auditable representation that all other runtimes can access, and upon which constitutional operations are authorized and executed.

## RS-12: Internal Processes

**Section Title (R0 §4.1):** Internal Processes

**Identifier:** RS-12

**Naming Convention:** RT05-PROC-NN

---

### RT05-PROC-01: Object Registration

**Trigger:** AtomicCommitAuthorization (RT05-IN-01) received from RT-03 for a new object creation.

**Constitutional steps:**
1. Verify the AtomicCommitAuthorization is valid and references a completed Gate 1-6 evaluation from RT-03
2. Extract identity token (from RT-01 IdentityResolutionResult embedded in the authorization)
3. Verify the specified D0/D1 category assignment is in the Constitutional Category Registry (RT05-STATE-07); if not present, initiate RT05-FAIL-04 (Ontology Boundary Violation)
4. Create the URO in the Active Object Register (RT05-STATE-01) with PENDING lifecycle state
5. Proceed to RT05-PROC-10 (Stage 8 Execution) to move from PENDING to ACTIVE
6. Upon Stage 8 confirmation: update lifecycle state to ACTIVE; create ObjectLifecycleRecord (RT05-OWN-08); create ObjectProvenanceRecord (RT05-OWN-03)

**Output:** URO created in Active Object Register; ObjectLifecycleRecord and ObjectProvenanceRecord issued

---

### RT05-PROC-02: Object Validation

**Trigger:** New URO created in PENDING state; also triggered periodically by RT05-PROC-09 (Fabric Integrity Verification).

**Constitutional steps:**
1. Verify URO has a valid RT-01 identity token bound (RT05-INV-01); if absent, initiate RT05-FAIL-01
2. Verify URO has a D0/D1 category assignment present in Constitutional Category Registry (RT05-INV-04); if absent, initiate RT05-FAIL-04
3. Verify URO has a provenance chain entry (RT05-INV-02); if absent, initiate RT05-FAIL-02
4. Verify URO attributes are within category bounds (RT05-INV-07); if exceeded, initiate RT05-FAIL-04
5. Record validation result in ObjectLifecycleRecord

**Constitutional invariant:** RT05-INV-04 — no URO may exist in the Active Object Register without passing RT05-PROC-02 validation.

**Output:** URO validated; validation result recorded

---

### RT05-PROC-03: Gate 2 State Assessment

**Trigger:** Gate2StateQuery (RT05-IN-05) received from RT-03.

**Constitutional steps:**
1. Identify the target URO from the query parameters
2. Apply a temporary LOCKED state to the target URO in the Object Lifecycle State Map (RT05-STATE-08) to prevent concurrent modification during query processing
3. Retrieve current URO lifecycle state, category assignment, provenance chain completeness, coherence state, and lock status
4. Construct ObjectStateResult (RT05-OUT-01) containing: URO identifier, current lifecycle state, constitutional validity (VALID/INVALID/LOCKED), coherence state, category assignment, and query timestamp
5. Release the temporary LOCKED state after ObjectStateResult is issued
6. Update Coherence State Map (RT05-STATE-04) if coherence was assessed during this query

**Constitutional invariant:** RT05-INV-10 — ObjectStateResult must accurately reflect the constitutional state at the moment of query; Gate 2 accuracy is constitutionally critical.

**Output:** ObjectStateResult (RT05-OUT-01) to RT-03

---

### RT05-PROC-04: Relationship Validation

**Trigger:** RelationshipUpdateRequest (RT05-IN-08) received; or during RT05-PROC-09 integrity verification.

**Constitutional steps:**
1. Verify the relationship type is specified in D3 Constitutional Relationship types (Constitutional Category Registry RT05-STATE-07); if not, initiate RT05-FAIL-03
2. Verify both source and target UROs exist in Active Object Register (RT05-STATE-01) with ACTIVE lifecycle state
3. Verify the relationship is authorized by AtomicCommitAuthorization (RT05-IN-08 must carry authorization reference)
4. Create or update RelationshipRecord (RT05-OWN-04)
5. Update Relationship Graph State (RT05-STATE-02)
6. Attach provenance to RelationshipRecord

**Output:** RelationshipRecord created/updated; Relationship Graph State updated

---

### RT05-PROC-05: Provenance Attachment

**Trigger:** Every authorized URO state transition (creation, modification, supersession).

**Constitutional steps:**
1. Create ObjectProvenanceRecord (RT05-OWN-03) for the transition:
   a. Operation identifier (from RT-03 AtomicCommitAuthorization)
   b. Authorizing actor identity token
   c. Authority type invoked
   d. Prior state reference (hash or reference to previous URO state)
   e. Resulting state reference
   f. Timestamp
2. Append ObjectProvenanceRecord to the URO's provenance chain in Provenance Chain Registry (RT05-STATE-03)
3. Update the URO record to reference the new provenance chain tail

**Constitutional invariant:** RT05-INV-02 — provenance must be attached before the URO state transition is considered complete.

**Output:** ObjectProvenanceRecord created; provenance chain extended

---

### RT05-PROC-06: State Transition Management

**Trigger:** Authorized lifecycle state transition for a URO.

**Constitutional steps:**
1. Verify transition is constitutionally valid (allowed transitions per RS-15 state machine)
2. Verify AtomicCommitAuthorization covers the transition
3. Execute transition in Object Lifecycle State Map (RT05-STATE-08)
4. Update ObjectLifecycleRecord (RT05-OWN-08) with new state and transition timestamp
5. Trigger RT05-PROC-05 (Provenance Attachment) for the transition
6. If transition is to ARCHIVED: remove from Active Object Register (RT05-STATE-01) but retain in Object Lifecycle Registry (RT05-MAN-07)

**Output:** URO lifecycle state updated; ObjectLifecycleRecord extended; provenance attached

---

### RT05-PROC-07: Coherence Assessment

**Trigger:** After every state transition; upon receipt of CoherenceViolationSignal (RT05-IN-10) from RT-03; periodic assessment.

**Constitutional steps:**
1. Assess the affected URO's internal coherence: are all attributes consistent within the constitutional category bounds?
2. Assess the URO's coherence with related UROs: do relationship references remain valid?
3. Assess fabric-wide coherence: does the recent state change introduce any cross-URO incoherence?
4. Update CoherenceStateRecord (RT05-OWN-05) for the affected URO
5. Update Coherence State Map (RT05-STATE-04)
6. If incoherence detected: initiate RT05-FAIL-05 (Coherence State Corruption)
7. Issue CoherenceStateReport (RT05-OUT-06) to RT-04 and RT-03

**Output:** CoherenceStateRecord updated; CoherenceStateReport issued

---

### RT05-PROC-08: Contradiction Processing

**Trigger:** Two or more UROs or URO states are detected that represent contradictory constitutional realities for the same entity.

**Constitutional steps:**
1. Identify both (or all) contradicting representations by URO identifier and attribute set
2. Verify each representation's provenance chain is complete and each was constitutionally authorized
3. Create ContradictionRecord (RT05-OWN-09) referencing all contradicting representations
4. Preserve all contradicting URO representations — do NOT remove or suppress either (RT05-INV-08)
5. Update Contradiction Register (RT05-STATE-06) with OPEN status
6. Issue ContradictionRecord (RT05-OUT-08) to RT-04 (for audit) and RT-09 (for epistemic processing)
7. Update lifecycle state of contradicting UROs to CONTRADICTED in Object Lifecycle State Map

**Constitutional invariant:** RT05-INV-08 — contradictory representations are preserved; RT05-PROH-04 prohibits removal.

**Output:** ContradictionRecord created; both representations preserved; RT-04 and RT-09 notified

---

### RT05-PROC-09: Fabric Integrity Verification

**Trigger:** Periodic integrity cycle; after critical state changes; upon RT-04 audit request.

**Constitutional steps:**
1. Verify all UROs in Active Object Register (RT05-STATE-01) have valid identity tokens (RT05-INV-01)
2. Verify all UROs have provenance chains (RT05-INV-02)
3. Verify all relationships in Relationship Graph State (RT05-STATE-02) reference valid, ACTIVE UROs (RT05-INV-03)
4. Verify all URO category assignments are in Constitutional Category Registry (RT05-INV-04)
5. Verify no extra-constitutional category assignments exist (RT05-INV-07)
6. Verify all Contradiction Registry entries are either OPEN (preserved) or RESOLVED (with adjudication reference)
7. Produce FabricIntegrityRecord (RT05-OWN-07) with verification results
8. Update Fabric Integrity State (RT05-STATE-09)
9. If any integrity violation detected: initiate the corresponding RT05-FAIL mode

**Output:** FabricIntegrityRecord; Fabric Integrity State updated; RT-04 notified via FabricIntegrityRecord

---

### RT05-PROC-10: Stage 8 Execution

**Trigger:** AtomicCommitAuthorization received from RT-03; target URO in PENDING state in Pending Commit Queue (RT05-STATE-10).

**Constitutional steps:**
1. Retrieve the operation from Pending Commit Queue
2. Verify AtomicCommitAuthorization is still valid (not revoked)
3. Execute the authorized state change:
   a. For object creation: create URO with ACTIVE state in Active Object Register
   b. For object mutation: apply authorized attributes to existing ACTIVE URO
   c. For object supersession: transition URO to SUPERSEDED and create new ACTIVE URO
4. Trigger RT05-PROC-05 (Provenance Attachment) simultaneously with state change execution — these are constitutionally indivisible within RT-05 Stage 8
5. If state change and provenance attachment both succeed: issue AtomicCommitConfirmation (RT05-OUT-02) to RT-03
6. If either step fails: do NOT issue AtomicCommitConfirmation; issue Stage 8 Failure Notification; initiate RT05-FAIL-01

**Constitutional invariant:** RT05-INV-09 — state change execution requires prior AtomicCommitAuthorization; RT05-OBL-07 — confirmation only after successful execution.

**Output:** URO state changed; ObjectProvenanceRecord created; AtomicCommitConfirmation issued to RT-03

Every constitutional object with a valid RT-01 identity resolution record has a corresponding URO in RT-05's Active Object Register. The Active Object Register is never a strict subset of the constituted object population — every constituted object must be represented.

**Violation detection:** PROC-05 (Provenance Attachment) validates chain continuity on each append. PROC-09 performs periodic full chain integrity checks. Triggers RT05-FAIL-02.

**Authority source:** D5 §5.3 (provenance requirements), D6 §6.4 (audit trail integrity).

The Reality Fabric Graph contains no orphaned relationships. Every relationship stored in the graph has both endpoint URO identifiers present in the Active Object Register at the time of relationship creation. Archived or superseded UROs referenced by historical relationships are tracked in the Object Lifecycle Registry.

**Violation detection:** PROC-04 (Relationship Validation) checks endpoint existence before relationship creation. PROC-09 audits existing relationships. Triggers RT05-FAIL-03.

**Authority source:** D3 §3.4 (relationship integrity), D2 §2.5 (relationship specifications).

### RT05-INV-04: Coherence State Currency

No URO's CoherenceStateRecord is older than the most recent state change affecting that URO. Coherence assessments are refreshed immediately following any state transition that affects the URO's constitutional relationships, provenance, or category membership.

**Authority source:** D3 §3.6 (coherence requirements), D8 TI-4 (operational state translation).

**Authority source:** R3 §RS-12 PROC-08 (Stage 8 authorization), D6 §6.2 (decision authority requirement).

All ObjectStateResult outputs are computed from the current Active Object Register state at the moment of the Gate2StateQuery. Cached, projected, or stale state is never used to answer a Gate 2 query. The computation timestamp is included in the ObjectStateResult.

**Violation detection:** PROC-03 (Gate 2 State Assessment) enforces live-register computation. Any cached-result path is constitutionally prohibited. Triggers RT05-FAIL-06.

**Authority source:** R3 §RS-12 Gate 2 specification, D6 §6.3 (observation authority constraints).

**Authority source:** R7 §RS-06 (temporal authority scope), D7 §7.2 (temporal validity requirements).

## RS-21: Failure Modes

**Severity:** CRITICAL — incomplete fabric representation compromises Gate 2 accuracy and constitutional coverage.

**Required response:** RT05-REC-01 (URO Representation Recovery). Suspend new Gate 2 queries until gap resolved. Issue FabricIntegrityRecord with severity CRITICAL. Notify RT-04 and RT-03.

**Description:** A URO's ObjectProvenanceRecord sequence contains a gap (missing intermediate record), duplication (same transition recorded twice), or falsification (transition record without corresponding ObjectLifecycleRecord). The constitutional audit trail is compromised.

**Violated invariant:** RT05-INV-02 (Provenance Chain Completeness).

**Detection:** PROC-05 validates chain continuity on each append. PROC-09 performs full chain traversal during integrity verification cycles.

**Severity:** HIGH — broken provenance undermines RT-04 audit capability and D5 provenance guarantees.

**Required response:** RT05-REC-02 (Provenance Chain Reconstruction). Issue FabricIntegrityRecord with severity HIGH. Notify RT-04 immediately — audit may be in progress.

**Violated invariant:** RT05-INV-03 (Relationship Endpoint Validity).

### RT05-FAIL-04: Coherence State Staleness

**Violated invariant:** RT05-INV-04 (Coherence State Currency).

**Detection:** PROC-07 is triggered by state transitions. PROC-09 compares CoherenceStateRecord timestamps against ObjectLifecycleRecord timestamps for the same URO.

**Severity:** MEDIUM — stale coherence may produce incorrect Gate 2 coherence assessments but does not directly corrupt the fabric graph.

**Detection:** PROC-10 requires AtomicCommitAuthorization as precondition. PROC-09 cross-references lifecycle records against authorization records.

**Severity:** CRITICAL — unauthorized state changes violate the constitutional enforcement model and may indicate systemic integrity failure.

**Required response:** RT05-REC-05 (Unauthorized Transition Quarantine). Immediate notification to RT-04 and RT-03. Suspend all further state transitions until RT-04 audit clears.

### RT05-FAIL-06: Gate 2 Inaccuracy

**Description:** An ObjectStateResult does not accurately reflect the actual constitutional state of the queried object at query time. The result may be computed from stale data (cached), from projected state, or may contain a computational error.

**Violated invariant:** RT05-INV-06 (Gate 2 Current State Computation), RT05-INV-10 (Gate 2 Accuracy).

**Detection:** RT-04 audit compares ObjectStateResult outputs against actual register state for sampled queries. RT-03 may detect inconsistencies between Gate 2 results and subsequent operational behavior.

**Severity:** CRITICAL — Gate 2 inaccuracy corrupts RT-03 enforcement decisions and may authorize unconstitutional operations or block constitutional ones.

**Violated invariant:** RT05-INV-08 (Contradiction Preservation).

## RS-22: Recovery Procedures

**Identifier:** RS-22
**Title:** Recovery Procedures for RT-05 Failure Modes

Each recovery procedure is paired to its corresponding failure mode(s) in RS-21. Recovery procedures must be executed in the specified order. Partial recovery that leaves the system in an inconsistent state is itself a failure requiring RT04 audit review.

### RT05-REC-01: URO Representation Recovery

**Triggered by:** RT05-FAIL-01 (URO Representation Gap).

**Procedure:**
1. Identify all constitutional objects with valid RT-01 identity resolution records missing from Active Object Register (gap census).
2. For each missing object, retrieve the RT-01 IdentityResolutionResult and construct a URO registration request.
3. Process URO registration through PROC-01 with provenance anchored to the gap detection event (not back-dated to original constitution event, which would falsify provenance).
4. Mark reconstructed URO entries with reconstruction flag in ObjectProvenanceRecord.
5. Suspend new Gate 2 queries for affected object categories during recovery.
6. Issue FabricIntegrityRecord documenting gap census, reconstruction steps, and reconstruction timestamps.
7. Notify RT-04 with complete gap census for audit review.
8. Notify RT-03 that Gate 2 accuracy was compromised during the gap period.
9. Resume normal operations when all gaps resolved and FabricIntegrityRecord issued.

### RT05-REC-02: Provenance Chain Reconstruction

**Triggered by:** RT05-FAIL-02 (Provenance Chain Break).

**Procedure:**
1. Locate the last valid provenance anchor — the most recent ObjectProvenanceRecord with a verified corresponding ObjectLifecycleRecord.
2. Reconstruct the provenance chain from the valid anchor to the present using the Object Lifecycle Registry audit trail as evidence.
3. Mark all reconstructed chain segments with reconstruction flag and reconstruction timestamp.
4. If reconstruction is incomplete (insufficient audit trail), record the gap as an unresolvable provenance breach in a ContradictionRecord.
5. Issue FabricIntegrityRecord with chain reconstruction details.
6. Notify RT-04 immediately — an active audit may be relying on the broken chain. Provide reconstructed chain and gap census.
7. Resume normal provenance attachment after reconstruction.

### RT05-REC-03: Orphaned Relationship Resolution

**Triggered by:** RT05-FAIL-03 (Orphaned Relationship).

**Procedure:**
1. Identify all orphaned relationships (endpoint URO not in Active Object Register or Object Lifecycle Registry).
2. Quarantine orphaned relationships — move to Contradiction Registry pending resolution.
3. For each orphaned relationship, attempt re-link: query RT-01 for identity resolution of the orphaned URO identifier. If found in Object Lifecycle Registry as archived, re-link to archived entry with annotation.
4. If re-link is impossible (identifier unknown to RT-01 and not in lifecycle registry), create ContradictionRecord documenting the unresolvable orphan.
5. Issue FabricIntegrityRecord with orphan census and resolution outcomes.
6. Notify RT-04 of unresolvable orphans for audit investigation.

### RT05-REC-04: Coherence State Refresh

**Triggered by:** RT05-FAIL-04 (Coherence State Staleness).

**Procedure:**
1. Identify all UROs whose CoherenceStateRecord timestamp predates their most recent ObjectLifecycleRecord timestamp (staleness census).
2. For each stale URO, invoke PROC-07 (Coherence Assessment) to compute a fresh coherence state.
3. Update CoherenceStateRecord with fresh assessment and a staleness-recovery annotation.
4. Record the refresh event in the FabricIntegrityLog.
5. Resume normal operations. Staleness recovery does not require RT-04 notification unless the scope exceeds ten UROs or CRITICAL UROs are affected.

### RT05-REC-05: Unauthorized Transition Quarantine

**Triggered by:** RT05-FAIL-05 (Unauthorized State Transition).

**Procedure:**
1. Identify the URO(s) affected by the unauthorized transition.
2. Quarantine affected UROs: set lifecycle state to LOCKED pending investigation.
3. Freeze further state transitions for quarantined UROs.
4. Issue a FabricIntegrityRecord with severity CRITICAL documenting the unauthorized transition.
5. Notify RT-04 immediately with: URO identifier, transition type, transition timestamp, and absence of AtomicCommitAuthorization record.
6. Notify RT-03 that an unauthorized transition has occurred.
7. Do NOT revert the unauthorized state change without explicit RT-03 AtomicCommitAuthorization for the reversion — reverting without authorization would itself be an unauthorized transition.
8. Maintain quarantine until RT-04 audit investigation concludes and RT-03 issues authorization for resolution.

### RT05-REC-06: Gate 2 Recalibration

**Triggered by:** RT05-FAIL-06 (Gate 2 Inaccuracy).

**Procedure:**
1. Suspend Gate 2 responses immediately. Queue incoming Gate2StateQuery requests for processing after recalibration.
2. Identify the source of inaccuracy: stale cache, projection error, or computational error.
3. If cache: purge all cached ObjectStateResult computations. Enforce live-register computation going forward.
4. Recompute ObjectStateResult for all queries received during the inaccuracy window using current Active Object Register state.
5. Issue corrected ObjectStateResult for any queries where RT-03 received an inaccurate result — notify RT-03 of corrections.
6. Issue FabricIntegrityRecord with severity CRITICAL documenting: inaccuracy period, identified source, correction scope, and corrected results.
7. Notify RT-04 — Gate 2 inaccuracy may have affected enforcement decisions during the inaccuracy window.
8. Resume Gate 2 operations with live-register computation confirmed active.

### RT05-REC-07: Contradiction Record Reconstruction

**Triggered by:** RT05-FAIL-07 (Contradiction Suppression).

**Procedure:**
1. Audit the Fabric Integrity Log and Object Lifecycle Registry for events that indicate contradictory state assertions that were not routed to PROC-08.

**EO-10: Temporal Signal Integration**

## RS-32: Architectural Boundaries

**Identifier:** RS-32
**Title:** RT-05 Architectural Boundaries

This section specifies what RT-05 owns, what it does not own, and the boundary conditions that govern interactions at the limits of RT-05's constitutional scope.

### What RT-05 Owns

RT-05 is the sole owner of the constitutional objects defined in RS-07:
- All URO instances (RT05-OWN-01) — the canonical representation of constitutional objects in the Reality Fabric
- The Reality Fabric Graph (RT05-OWN-02) — the constitutional graph of UROs and their relationships
- All ObjectProvenanceRecords (RT05-OWN-03) — the constitutional provenance chains
- All RelationshipRecords (RT05-OWN-04) — the relationship graph entries
- All CoherenceStateRecords (RT05-OWN-05) — the coherence assessments
- All TemporalValidityRecords (RT05-OWN-06) — the temporal state records
- All FabricIntegrityRecords (RT05-OWN-07) — the integrity audit trail
- All ObjectLifecycleRecords (RT05-OWN-08) — the state transition history
- All ContradictionRecords (RT05-OWN-09) — the contradiction registry

Ownership means: only RT-05 may create, modify, or archive these objects. Other runtimes receive copies or references as outputs (RS-09) but do not own the canonical records.

### What RT-05 Does Not Own

RT-05 does not own and must not claim ownership over:

| Domain | Owner |
|--------|-------|
| Identity records | RT-01 |
| Authority records and authority claims | RT-02 |
| Enforcement records, gate logs, AtomicCommitAuthorization | RT-03 |
| Audit records, AuditReport, AuditCycleRecord | RT-04 |
| Constitutional ontology definitions (D0/D1 categories) | D0, D1 (immutable) |
| Temporal authority records | RT-07 |
| Observation records | RT-08 |
| Knowledge claims and knowledge graph | RT-09 |

### Boundary Conditions

**BC-01: URO vs. Identity Record**
The URO (RT05-OWN-01) is RT-05's representation of a constitutional object within the Reality Fabric. The identity record (RT-01) is the authoritative identity assertion. These are distinct objects at different constitutional layers. RT-05's URO references the RT-01 identity record but does not incorporate or duplicate it.

**BC-02: RelationshipRecord vs. Relationship Authority**
RT-05 records relationships (RT05-OWN-04) in the Reality Fabric Graph but does not define relationship types or authorities. Relationship type definitions are D1/D3 constitutional specifications. RT-06 holds Relationship authority. RT-05 is the implementation point: it validates and records, it does not define or authorize.

**BC-03: CoherenceState vs. Truth Claim**
RT-05 CoherenceStateRecords (RT05-OWN-05) assess whether a URO's state is internally consistent within the constitutional framework. Coherence is not a truth claim — RT-05 does not assert that the constitutional object accurately represents external reality. Coherence is a constitutional consistency assessment, not an epistemological claim.

**BC-04: ContradictionRecord vs. Contradiction Resolution**
RT-05 preserves contradictions (RT05-INV-08) but does not resolve them. A ContradictionRecord (RT05-OWN-09) is a constitutional fact: two incompatible state assertions exist for the same object. Resolution — deciding which is authoritative — is outside RT-05's scope and belongs to the constitutional authority that created the conflicting assertions.

## RS-34: Implementation Constraints

**Identifier:** RS-34
**Title:** Prohibitions — RT-05 Constitutional Implementation Constraints

The following prohibitions define what RT-05 must never do. Each prohibition is an absolute constraint — no operational condition, authority claim, or performance optimization justifies violating a prohibition. Violation of any prohibition constitutes an RT05-FAIL event requiring RT-04 audit.

### RT05-PROH-01: No Self-Authorization

RT-05 must never authorize its own state changes. RT-05 holds Object State authority (RS-06) but no Decision authority. The authority to decide that a state change should occur rests with RT-03 (for enforcement-mediated changes). RT-05 may not create AtomicCommitAuthorization for its own operations.

**Rationale:** Self-authorization would collapse the constitutional separation between Object State authority (what exists) and Decision authority (what should change). RT-05 managing its own operations outside RT-03 authorization would create an unauditable power.

### RT05-PROH-02: No Truth Determination

RT-05 must never determine whether a reality representation is "true" in the sense of accurately reflecting external reality. RT-05 assesses constitutional coherence (internal consistency within the constitutional framework) — this is not a truth claim. RT-05 must never assert that a URO's state accurately or inaccurately reflects the world outside the APEX constitutional architecture.

**Rationale:** Truth determination is an epistemological function belonging to RT-09 (Knowledge) operating under D9 and D10 constraints. RT-05's scope is constitutional representation, not epistemological validation.

### RT05-PROH-03: No Ontology Creation

RT-05 must never create new constitutional categories, object types, or ontological definitions. The Constitutional Category Registry (RT05-STATE-07) is populated from D0 and D1 at founding — RT-05 reads it but does not extend it. Any apparent need for a new category is a signal for constitutional amendment through the A0 process, not a RT-05 operation.

**Rationale:** Ontology is specified at the D-layer (D0, D1) of the constitutional hierarchy. RT-05 operates at the R-layer. R-layer runtimes implement D-layer specifications; they do not create new D-layer content.

### RT05-PROH-04: No Knowledge Claims

RT-05 must never assert knowledge about the external world beyond constitutional object state. RT-05 may state what is registered in the Active Object Register. RT-05 may not infer, project, or assert facts about reality beyond what is constitutionally registered.

**Rationale:** Knowledge claims are RT-09's domain. RT-05 confining itself to constitutional registration maintains clean separation between what is constitutionally represented (RT-05) and what is known (RT-09).

### RT05-PROH-05: No Authority Creation

RT-05 must never create, modify, extend, or delegate authority records. The five D6 authority types (Observation, Interpretation, Decision, Projection, Audit) are constituted at A0 founding and maintained by RT-02. RT-05 may not create new authority for itself or for other runtimes.

**Rationale:** Authority is RT-02's domain. RT-05 creating authority would undermine the constitutional authority model and create unaudited power pathways.

### RT05-PROH-06: No Contradiction Suppression

RT-05 must never suppress, silently resolve, overwrite, or discard a contradictory reality representation. When two incompatible state assertions exist for the same constitutional object, both must be preserved as a ContradictionRecord (RT05-OWN-09). Contradiction resolution is outside RT-05's scope.

**Rationale:** Contradiction suppression is a form of reality falsification. The constitutional architecture requires contradictions to be preserved and surfaced for audit review and constitutional resolution — not hidden by the fabric layer.

### RT05-PROH-07: No Backdated Provenance

RT-05 must never create a provenance record with a timestamp earlier than its actual creation time. Provenance records may reference historical events (founding, prior state transitions) but the provenance record itself must be dated to the moment it is created by RT-05. Reconstructed provenance records (per RT05-REC-02) must be marked with reconstruction flags and actual creation timestamps.

**Rationale:** Backdated provenance falsifies the audit trail. Even well-intentioned backdating (e.g., reconstructing a missing record) undermines the evidentiary value of provenance for RT-04 audit purposes.

### RT05-PROH-08: No Unauthorized State Changes

RT-05 must never change the state of any constitutional object in the Active Object Register, Reality Fabric Graph, provenance chain, or relationship records without a prior RT-03 AtomicCommitAuthorization in the Pending Commit Queue for that specific change.

**Rationale:** Unauthorized state changes are the primary threat to constitutional integrity. RT-05 executing state changes on its own initiative would make the enforcement-fabric pair (RT-03↔RT-05) fail as a constitutional safeguard.

### RT05-PROH-09: No Gate 2 Caching

RT-05 must never serve a Gate 2 ObjectStateResult computed from cached, projected, or previously computed state. Each Gate2StateQuery must result in a live computation from the current Active Object Register at the moment of the query. Performance optimizations that achieve this through caching or projection are constitutionally prohibited regardless of their accuracy claims.

**Rationale:** Gate 2 accuracy (RT05-INV-10) is a constitutional requirement, not a best-effort target. RT-03 enforcement decisions depend on Gate 2 accuracy. The risk of stale cache serving inaccurate state to RT-03 is constitutionally unacceptable — the live computation requirement eliminates this risk class entirely.

### RT05-PROH-10: No Audit Obstruction

RT-05 must never interfere with RT-04 audit operations, withhold records from RT-04 within the access rights specified in RS-23, modify records during an active RT-04 audit cycle within the freeze scope specified in AR-06, or take any action that degrades RT-04's ability to audit RT-05 operations.

**Rationale:** Audit obstruction would undermine the constitutional audit independence established by D6 AIR-5. RT-05 operating without effective RT-04 audit would create an unmonitorable power in the constitutional architecture — a constitutional hazard of the type described in P-AUD-1 (self-assessment circularity).

## RS-35: Prohibited Responsibilities

**PROH-RES-07: Knowledge Production**
RT-05 does not produce knowledge claims about constitutional objects or the external world. Knowledge is RT-09's function. RT-05 provides the constitutional object state from which RT-09 may derive knowledge — but RT-05 does not itself produce knowledge claims.

**PROH-RES-08: Constitutional Ontology Management**
RT-05 does not manage, extend, or revise the constitutional ontology (D0/D1 category specifications). Ontology management belongs to the D-layer constitutional specification process. RT-05 reads the ontology at founding (PRE-02) and applies it throughout its operational lifetime.
