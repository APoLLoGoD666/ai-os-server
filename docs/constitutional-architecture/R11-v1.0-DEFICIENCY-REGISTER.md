## Deficiency Classification Framework

**Class I — Critical Constitutional Defect**
Incorrect constitutional role, boundary violation, unauthorized authority, fatal conflict. Blocks certification.

**Class II — Material Certification Defect**
Non-canonical identifier, non-verbatim responsibility, undisclosed conflict, wrong PAIR characterization. Blocks unconditional certification.

**Class III — Minor Defect**
Transcription error, minor misattribution, recoverable without authority decision. Does not block certification; must be corrected.

**Class IV — Editorial / Traceability**
Citation imprecision, section number errors, formatting. Does not block certification; advisory.

## FAA-11-001 — D6 Source Section Citation Error

| Field | Value |
|---|---|
| **Finding ID** | FAA-11-001 |
| **Class** | IV — Editorial / Traceability |
| **Section Affected** | RS-06 (Authority) |
| **Constitutional Basis** | D6 §4.4 (Decision Authority); D6 §4.2–§4.6 (five authority types); D6 §4.7 (Authority Integrity Rules AIR-1–AIR-5) |

**Description:**
RS-06 cites "D-6 §4.3" as establishing "the five authority types (AIR-1 through AIR-5) and their constitutional definitions" and as the source for "AIR-3 (Decision Authority)." Three errors are present:
(a) D6 §4.3 is "Interpretation Authority" — not Decision Authority. Decision Authority is defined at D6 §4.4.
(b) D6 §4.3 does not "establish the five authority types" — §4.1 introduces the five types; §4.2–§4.6 each define one type.
(c) D6 does not number authority types as AIR-1 through AIR-5. D6 §4.7 uses AIR-1 through AIR-5 for Authority Integrity Rules (Anti-Collapse, No Unauthorized Projection, No Knowledge Monopolization, No Hidden Decisions, Audit Independence) — entirely different content. The AIR-N authority type numbering is A1's own convention, not D6's.

**Evidence:**

| Source | Section | Actual Content |
|---|---|---|
| D6-v1.0 | §4.3 | Interpretation Authority — right to apply registered interpretation protocols |
| D6-v1.0 | §4.4 | Decision Authority — right to form CivilizationalDecisions |
| D6-v1.0 | §4.7 | AIR-1: Authority Separation; AIR-2: No Unauthorized Projection; AIR-3: No Knowledge Monopolization; AIR-4: No Hidden Decisions; AIR-5: Audit Independence |
| A1-v1.2 | §5.1 | AIR-3 = Decide (A1's own convention for authority type numbering) |
| RS-06 | Authority Source | "D-6 §4.3 establishes the five authority types (AIR-1 through AIR-5)" |

**Remediation required:**
Correct RS-06 to cite D6 §4.4 as the source for Decision Authority. Replace "D-6 §4.3 establishes the five authority types (AIR-1 through AIR-5)" with "D6 §4.1 introduces five constitutional authority types (Observation §4.2, Interpretation §4.3, Decision §4.4, Projection §4.5, Audit §4.6). A1-v1.2 assigns these using AIR-N notation (AIR-3 = Decision Authority) in §5.1." Note that D6 §4.7's AIR-N notation refers to Authority Integrity Rules, not authority types.

**Certification impact:** Advisory only. Does not block certification. The correct authority (Decision Authority at civilizational scope) is unambiguously derivable through A1 §5.1.

## FAA-11-010 — FR-3 Mischaracterized in RT11-INV-5

| Field | Value |
|---|---|
| **Finding ID** | FAA-11-010 |
| **Class** | III — Minor Defect |
| **Section Affected** | RS-20, RT11-INV-5; RS-35, PROH-R7; RS-13 Forbidden Interactions |
| **Constitutional Basis** | A1-v1.2 §14.3 FR-3 (actual text) |

**Description:**
The specification characterizes FR-3 as prohibiting RT-11 deliberation on "its own constitutional status, its own authority boundaries, or its own authority boundaries." The actual A1 §14.3 FR-3 text is: "RT-11 deliberation may not reference a Decision it itself produced as evidence for the same deliberation cycle. Decision D cannot be used as evidence for the deliberation that produced D."

A1 FR-3 prohibits circular evidence (using RT-11's own decisions as evidence in the deliberation that produced them). The specification expands this to a broader prohibition on self-constitutional deliberation that is not what A1 FR-3 states. The prohibition the spec describes may be derivable from other constitutional principles, but FR-3 is not its source.

**Evidence:**
A1 §14.3 FR-3: "RT-11 deliberation may not reference a Decision it itself produced as evidence for the same deliberation cycle. Decision D cannot be used as evidence for the deliberation that produced D."

RT11-INV-5 (RS-20): "RT-11 may not conduct self-referential deliberation. Deliberation concerning RT-11 itself, its own constitutional status, or its own authority boundaries is constitutionally forbidden (A1 §14.3 FR-3)."

These are different prohibitions attributed to the same source.

**Remediation required:**
Correct RT11-INV-5 to accurately state A1 FR-3: "RT-11 deliberation may not reference a Decision it itself produced as evidence for the same deliberation cycle." If the self-constitutional deliberation prohibition is also intended, it must be sourced from its actual constitutional basis (which is not A1 FR-3). Correct the FR-3 citation in RS-35 PROH-R7 and RS-13 Forbidden Interactions table accordingly.

**Certification impact:** Minor — does not block certification independently.

## FAA-11-011 — Implementation-Level Data Types in RS-11 State Variable Definitions

| Field | Value |
|---|---|
| **Finding ID** | FAA-11-011 |
| **Class** | III — Minor Defect |
| **Section Affected** | RS-11 (Managed State) |
| **Constitutional Basis** | R0 CERT-09; D8 PROH-1 through PROH-9; R0 RQ-5, RQ-6 |

**Description:**
RS-11 state variable table includes data type designations: "String," "Enum," "Integer," "Timestamp," "Boolean," "Reference," "Set." These are implementation-level data type specifications that violate R0 CERT-09 (Implementation Independence Audit). R0 requires that every provision specifies WHAT not HOW, and that the specification be satisfiable by multiple different technical implementations. Data type designations (String, Integer, Timestamp, Boolean, etc.) constrain implementation choices and specify HOW state is stored at a technical level.

**Evidence:**
RS-11 state variable table (excerpt):
- `cum_version` | String | ...
- `cum_state` | Enum | ...
- `dum_receipt_count` | Integer | ...
- `cum_currency_timestamp` | Timestamp | ...
- `deliberation_active` | Boolean | ...
- `deliberation_record_ref` | Reference | ...
- `dum_manifest` | Set | ...

These type designations (String, Enum, Integer, Timestamp, Boolean, Reference, Set) are programming/data-model level constructs, not constitutional-level descriptions.

**Remediation required:**
Replace implementation data type column with constitutional characterizations. For example:
- `cum_version` | Constitutional identifier (unique, immutable per version) | ...
- `cum_state` | Constitutional lifecycle state | ...
- `dum_receipt_count` | Quantitative count (0–12) | ...
- `cum_currency_timestamp` | Temporal position of synthesis | ...
- `deliberation_active` | Constitutional flag | ...

This removes the implementation-level type constraint while preserving the constitutional state description.

**Certification impact:** Minor — does not independently block certification, but contributes to CERT-09 advisory.
