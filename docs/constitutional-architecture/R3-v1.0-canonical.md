## RS-03 — Runtime Purpose

RT-03 exists to guarantee that the constitutional requirements established in D-2 through D8 are not merely declared but enforced at the moment every constitutionally significant operation is presented for admission to the Reality Fabric.

### RS-03.1 — The Four Constitutional Enforcement Guarantees

**Guarantee 1 — No unattributed operation.** Every Class A operation admitted to the Reality Fabric is attributable to a specific, constitutionally resolved, active, non-suspended actor. RT-03 provides this guarantee through Gate 1 (identity) and Stage 9 (provenance recording, constitutionally indivisible from Stage 8 state change).

**Guarantee 2 — No unauthorized operation.** Every Class A operation admitted to the Reality Fabric was performed by an actor with valid, scoped, unrevoked authority for that specific operation. RT-03 provides this guarantee through Gate 3 (authority, calling RT-02).

**Guarantee 3 — No constitutively impossible state.** Every admitted operation produces a constitutionally possible state. Operations that would create logically impossible configurations, delete constitutional objects, introduce provenance cycles, or violate structural immutability never enter the Reality Fabric. RT-03 provides this guarantee through Gate 5 (constitutive coherence).

**Guarantee 4 — No lost provenance.** Every admitted operation has a provenance record constitutionally inseparable from the state change it records. If the state change cannot be recorded with full provenance, it does not occur. RT-03 provides this guarantee through Stage 8-9 atomicity (RT03-INV-3).

### RS-03.2 — What RT-03 Does Not Do

RT-03 does not create constitutional rules — D-2 through D8 do. RT-03 does not interpret ambiguous constitutional provisions — it generates CCRs and suspends the affected stream. RT-03 does not possess independent constitutional authority — its authority derives from the FoundingKernel DelegationRecord established at FoundingRatification. RT-03 does not make civilizational decisions. RT-03 does not maintain identity, authority, or knowledge records. RT-03 enforces; it does not originate.

## RS-04 — Runtime Scope

### RS-04.1 — In Scope

1. **Class A operation processing.** Every actor-originated (Class A) constitutional operation — regardless of which runtime the actor belongs to — is within RT-03's mandatory processing scope. No Class A operation may bypass RT-03.

2. **Six-gate constitutional evaluation.** The evaluation of every Class A operation against all six constitutional gates (Identity, Object State, Authority, Epistemic, Constitutive Coherence, Temporal/Historical Integrity) is within RT-03's exclusive scope.

3. **Stage 8-9 atomic commit authorization.** RT-03 authorizes RT-05 to execute the atomic fabric commit at Stage 8 and produces the provenance record at Stage 9. Both stages are constitutionally indivisible.

4. **Stage 10 coherence evaluation initiation.** RT-03 initiates Stage 10 post-commit coherence evaluation by signaling RT-06 to open the Mandatory Propagation Window (MPW).

5. **Class B Kernel Manifest operation execution.** Generating all eleven Class B output types enumerated in the Kernel Operation Manifest (KOM) is within RT-03's exclusive scope. No other runtime may generate Class B outputs.

6. **Kernel Operation Manifest custody.** Maintaining the KOM as a finite, closed enumeration of permitted Class B operation types is within RT-03's exclusive scope.

7. **Suspension authority.** Issuing Suspension Notices (Type A Operational Suspension; Type B Authority Suspension) and Domain Processing Suspensions (Type C) under the conditions specified in D4 Part 10 is within RT-03's scope.

8. **Open register maintenance.** Maintaining the Open Action Register, Open Challenge Register, Coherence Violation Register, and Reality Gap Register is within RT-03's scope.

### RS-04.2 — Out of Scope

1. **Identity resolution.** RT-03 calls RT-01 at Gate 1 but does not perform identity resolution itself.

2. **Authority record maintenance.** RT-03 calls RT-02 at Gate 3 but does not maintain authority records.

3. **Epistemic chain evaluation beyond gate validation.** RT-03 validates epistemic chain completeness at Gate 4 by querying RT-09. RT-03 does not maintain or evaluate the epistemic content of knowledge claims.

4. **Reality Fabric object ownership.** RT-03 does not own or manage URO objects in the Reality Fabric. RT-05 owns fabric objects; RT-03 authorizes their admission.

5. **Constitutional rule creation.** RT-03 enforces constitutional rules; it does not create them. Constitutional silence is not authorization.

6. **RT-04 audit operations.** RT-04 audit operations are constitutionally excluded from RT-03 processing (RT03-INV-6). RT-04 is not a Class A actor subject to RT-03 gate enforcement for its own audit operations.

7. **Founding authority decisions.** Constitutional decisions requiring founding-level authority (RT-16 amendments) are not within RT-03's scope to make — only to enforce once made.

## RS-07 — Owned Constitutional Objects

RT-03 exclusively owns the following constitutional objects. No other runtime may create, modify, or terminate these objects.

### RT03-OWN-01: RejectionRecord

**Definition:** A constitutional record documenting the rejection of a Class A operation at a specific gate, specifying the gate, the specific condition not satisfied, the actor, the proposed operation type, the timestamp, and any relevant constitutional references.

**Constitutional basis:** D4 §4.1-4.6 (gate failure records); KI-013; D8 PROH-5 (permanent — never deleted).

**State:** Immutable upon creation. Permanent — terminal state is Historical (never deleted).

**Creation trigger:** Any gate failure during Class A operation processing (RT03-OBL-12).

### RT03-OWN-02: AccountabilityRecord

**Definition:** A constitutional record documenting the successful admission of a Class A operation, constitutionally inseparable from the Stage 8 state change it records. The AccountabilityRecord provides the provenance for every admitted operation — who performed it, under what authority, at what time, and with what constitutional effect.

**Constitutional basis:** D4 §3 (Stage 9); RT03-INV-3; RT03-INV-8; KI-014; D3 RF-A8; D8 IOR-2.

**State:** Immutable upon creation. Permanent.

**Creation trigger:** Successful Stage 8-9 atomic commit (RT03-OBL-08).

### RT03-OWN-03: Rollback Provenance Record

**Definition:** A constitutional record documenting the failure of a Stage 8-9 atomic commit attempt — the state change and provenance recording failed as an indivisible unit. The Rollback Provenance Record is itself a Class B output, establishing that an atomic commit was attempted but did not complete.

**Constitutional basis:** D4 §3 (Stage 8 failure handling); RT03-INV-3.

**State:** Immutable upon creation. Permanent.

**Creation trigger:** Stage 8-9 atomicity failure (RT03-OBL-08 failure condition).

### RT03-OWN-04: Suspension Notice

**Definition:** A constitutional record issuing a Type A (Operational), Type B (Authority), or Type C (Domain Processing) suspension under the D4 Part 10 constitutional conditions. The Suspension Notice specifies the suspension type, target, constitutional trigger, issuing authority, and duration or recovery condition.

**Constitutional basis:** D4 Part 10; KI-018 (Type A effect); KI-019 (Type B trigger via authority challenge).

**State:** Active until superseded by a ResolutionRecord. Permanent record.

**Creation trigger:** Constitutional suspension conditions per D4 §10.2 (Type A), §10.3 (Type B), §10.4 (Type C).

### RT03-OWN-05: CoherenceResolutionEvent (CRE)

**Definition:** A constitutional record produced at Stage 10 identifying a conditional coherence condition created by an admitted operation. A CRE specifies the admitted operation that triggered evaluation, the specific D3 GCR or fabric invariant implicated, all objects involved, whether the condition is resolvable, and the CoherenceStatus flag to set.

**Constitutional basis:** D4 §9.2; D3 GCR-1 through GCR-7.

**State:** Immutable upon creation. Permanent.

**Creation trigger:** Stage 10 post-commit coherence evaluation (RT03-OBL-09).

### RT03-OWN-06: Constitutional Clarification Request (CCR)

**Definition:** A constitutional record generated when RT-03 encounters a constitutional condition for which no Manifest operation and no explicit constitutional rule provides a determinate answer. The CCR identifies the specific constitutional silence, the affected operation stream, and the suspended processing state.

**Constitutional basis:** D4 §2.6 (Kernel Non-Exemption Principle); RT03-OBL-13.

**State:** Open (stream suspended) or Resolved (stream resumed). Permanent record.

**Creation trigger:** Constitutional silence condition detection (RT03-OBL-13).

## RS-12 — Internal Processes

### RT03-PROC-01: Stage 1 — Intent Registration

**Trigger:** Receipt of RT03-IN-01 (ClassAOperationProposal).

**Constitutional steps:**
1. Assign a unique constitutional operation identifier
2. Create an Operation Lifecycle Record (RT03-OWN-09) in Stage 1 state
3. Extract from the proposal: actor identity claim, operation type, target object references, epistemic grounding claim, provenance context
4. Log the intake in RT03-STATE-10 (Kernel Operation Log)
5. Advance the operation to Stage 2 (Gate 1)

**Note:** Stage 1 is not a gate. It is intake registration. No constitutional evaluation occurs at Stage 1. The operation receives a constitutional existence at Stage 1 — it is now tracked.

### RT03-PROC-02: Stage 2 — Gate 1 (Identity Resolution)

**Trigger:** Operation Lifecycle Record advancing from Stage 1.

**Constitutional steps:**
1. Issue RT03-OUT-01 (Gate1Query) to RT-01 with the actor identity claim
2. Receive RT03-IN-02 (IdentityResolutionResult) from RT-01
3. Evaluate D4 §4.1 conditions (a) through (d)
4. If all conditions satisfied: record Gate 1 PASS in Operation Lifecycle Record; advance to Stage 3
5. If any condition not satisfied: generate RejectionRecord (RT03-OWN-01) specifying Gate 1, the specific failed condition, and all required fields; log in RT03-STATE-02; terminate operation processing

**Failure exit:** RT03-FAIL-02 (Missing Identity Basis) — RT-01 cannot provide a definite result, or the actor identity cannot be resolved.

### RT03-PROC-03: Stage 3 — Gate 2 (Object and State Validation)

**Trigger:** Operation Lifecycle Record advancing from Stage 2 (Gate 1 PASS).

**Constitutional steps:**
1. Issue RT03-OUT-02 (Gate2Query) to RT-05 for each target object reference
2. Receive RT03-IN-03 (ObjectStateResult) from RT-05
3. Evaluate D4 §4.2 conditions: existence, lifecycle state operability, Reference Continuity for historical endpoints, ResolutionRecord exception for suspension lifts
4. If all conditions satisfied: record Gate 2 PASS; advance to Stage 4
5. If any condition not satisfied: generate RejectionRecord (Gate 2); terminate

**Failure exit:** RT03-FAIL-04 (Invalid Constitutional State Transition) if proposed lifecycle transition is forbidden.

### RT03-PROC-04: Stage 4 — Gate 3 (Authority Validation)

**Trigger:** Operation Lifecycle Record advancing from Stage 3 (Gate 2 PASS).

**Constitutional steps:**
1. Issue RT03-OUT-03 (Gate3Query) to RT-02 with actor identity reference, operation type, target scope
2. Receive RT03-IN-04 (AuthorityResolutionResult) from RT-02
3. If CONFIRMED: record Gate 3 PASS; advance to Stage 5
4. If DENIED: record Gate 3 FAIL with specific D4 §4.3 condition; generate RejectionRecord (Gate 3); terminate

**Failure exit:** RT03-FAIL-01 (Authority Ambiguity) — RT-02 cannot provide a definite result, or Under Authority Review flag is active with no alternative authority chain.

### RT03-PROC-05: Stage 5 — Gate 4 (Epistemic Validation)

**Trigger:** Operation Lifecycle Record advancing from Stage 4 (Gate 3 PASS).

**Constitutional steps:**
1. Issue RT03-OUT-04 (Gate4Query) to RT-09 for epistemic chain state
2. Receive RT03-IN-05 (EpistemicChainStateResult) from RT-09
3. Evaluate D4 §4.4 conditions (a) through (h): epistemic stage validity, prior chain object presence, KnowledgeClaim lineage, UnderstandingModel grounding, PossibilitySet coverage, CivilizationalAction governing decision, causal ordering, Observer calibration
4. If all conditions satisfied: record Gate 4 PASS; advance to Stage 6
5. If any condition not satisfied: generate RejectionRecord (Gate 4); terminate

**Failure exit:** RT03-FAIL-05 (Provenance Failure) — prior chain objects cannot be confirmed present in fabric.

### RT03-PROC-06: Stage 6 — Gate 5 (Constitutive Coherence Validation)

**Trigger:** Operation Lifecycle Record advancing from Stage 5 (Gate 4 PASS).

**Constitutional steps:**
1. Evaluate the proposed operation against all eight constitutively prohibited conditions in D4 §4.5 (a) through (h)
2. RT-03 performs this evaluation internally — it does not call an external runtime (Gate 5 is RT-03's own evaluation)
3. If any prohibited condition is detected: generate RejectionRecord (Gate 5) specifying the specific condition; the RejectionRecord is permanent regardless of any subsequent operation
4. If no prohibited condition: record Gate 5 PASS; advance to Stage 7

**Note:** Gate 5 evaluates constitutive (logical/ontological) impossibility only. Conditions that could be resolved through future operations are not rejected at Gate 5 — they are flagged at Stage 10. This distinction (D4 §9.1) must be maintained.

**Failure exit:** RT03-FAIL-07 (Enforcement Inconsistency) if the Gate 5 evaluation produces different results on re-evaluation of the same operation state.

### RT03-PROC-07: Stage 7 — Gate 6 (Temporal and Historical Integrity Validation)

**Trigger:** Operation Lifecycle Record advancing from Stage 6 (Gate 5 PASS).

**Constitutional steps:**
1. Evaluate the proposed operation against all six conditions in D4 §4.6 (a) through (f): causal ordering, backdating prohibition, lifecycle transition validity, era designation consistency, ChangeRecord integrity, HistoricalAnchor consistency
2. RT-03 performs this evaluation internally with access to the fabric's causal ordering records via RT-05
3. If any condition violated: generate RejectionRecord (Gate 6); terminate
4. If all conditions satisfied: record Gate 6 PASS; advance to Stage 8

**Failure exit:** RT03-FAIL-04 (Invalid Constitutional State Transition) if proposed lifecycle transition violates the object's lifecycle state machine.

### RT03-PROC-08: Stages 8-9 — Atomic Constitutional Commit

**Trigger:** Operation Lifecycle Record advancing from Stage 7 (Gate 6 PASS — all six gates passed).

**Constitutional steps:**
1. Issue RT03-OUT-06 (AtomicCommitAuthorization) to RT-05, authorizing the state change with the complete gate evaluation record
2. Receive RT03-IN-06 (AtomicCommitConfirmation) from RT-05 confirming the state change executed
3. Simultaneously produce AccountabilityRecord (RT03-OWN-02) as Stage 9 provenance: these two acts (Stage 8 state change + Stage 9 provenance record) are constitutionally indivisible
4. If the state change confirmed and provenance record created: record ADMITTED in Operation Lifecycle Record; log in RT03-STATE-10; deliver AccountabilityRecord to RT-05 and RT-04
5. If either step fails: generate Rollback Provenance Record (RT03-OWN-03); generate Kernel Failure Log entry (RT03-OWN-07); do not mark operation as ADMITTED; do not produce AccountabilityRecord claiming an uncommitted state change; advance to RT03-PROC-09 recovery

**Constitutional invariant:** RT03-INV-3 is absolute — Stage 8 and Stage 9 always succeed or fail together.

### RT03-PROC-09: Stage 10 — Post-Commit Coherence Evaluation Initiation

**Trigger:** Successful Stages 8-9 admission.

**Constitutional steps:**
1. Issue RT03-OUT-08 (Stage10Signal) to RT-06, specifying the admitted operation and the propagation frontier
2. Open the MPW tracking entry in RT03-STATE-09
3. Monitor MPW completion: if RT-06 signals CRE propagation complete within MPW, close the tracking entry
4. If MPW is exceeded: register in Coherence Violation Register (RT03-STATE-07); generate CCR if the propagation failure is systematic; generate Type C Domain Processing Suspension for the affected stream

**Note:** Stage 10 is not part of the atomic commit. RT-03 failure during Stage 10 does not un-commit the Stage 8-9 admission. On recovery, RT-03 re-executes Stage 10 from the last CRE stream position.

### RT03-PROC-10: Class B Manifest Operation Execution

**Trigger:** Constitutional trigger for any of the eleven Class B operation types.

**Constitutional steps:**
1. Verify the trigger matches a Class B operation type enumerated in the KOM (RT03-STATE-04)
2. If the trigger does not match any Manifest type: generate CCR (RT03-OBL-13); do not generate any unlisted output
3. Execute the Class B operation exactly as specified in the Manifest
4. Generate the specified constitutional output
5. Apply the Manifest-specified termination condition — the Class B operation terminates at its constitutionally defined output; no further Class B processing is generated by the Class B output itself
6. Log in RT03-STATE-10
