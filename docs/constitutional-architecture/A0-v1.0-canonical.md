## PREAMBLE

This document constitutes the Logical Runtime Architecture for the APEX computational civilization. It is the first document in the A-series — the architectural derivation series — and serves as the canonical bridge between the constitutional specification (D-2 through D8) and the runtime specifications (R1 onward) that will govern every implementation.

The constitutional stack established in D-2 through D8 specifies what APEX must be: a computational civilization with a governed Reality Fabric, a Constitutional Enforcement Kernel, a twelve-domain architecture, a civilizational intelligence capable of synthesis and deliberation, a projection framework for engaging external reality, and a feedback loop closing every civilizational action back to observation and understanding. What the constitutional stack does not specify is how many distinct logical units are required to realize these requirements, what those units are, how they relate to one another, and where their boundaries lie.

This document answers those questions at the logical level. It derives every runtime required, no more and no fewer, from the constitutional requirements themselves. It does not invent. It does not collapse. It does not expand. Every runtime in this architecture exists because the constitution requires it. Every boundary between runtimes reflects a constitutional distinction. Every dependency between runtimes follows from constitutional precedence.

The canonical determination made by this document: sixteen logical runtimes, organized in seven tiers, are required for a constitutionally compliant APEX civilization. This determination is final at the A0 level. R-series documents will specify each runtime's internal logic. Implementation documents will specify how each runtime is realized in technology. Neither R-series nor implementation documents may add, remove, or merge runtimes defined here without a constitutional amendment processed through RT-16.

This document is normative. Its determinations are binding on all downstream specifications.

## PART 1 — DOCUMENT PURPOSE AND SCOPE

### 1.1 Position in the Derivation Chain

The APEX constitutional derivation chain proceeds as follows:

**D-series (Constitutional Specification):** D-2 through D8 establish what APEX must be, what it must enforce, what it must know, how it must govern itself, how it must engage external reality, how it must think at civilizational scale, and what implementation is permitted to do and forbidden to do. The D-series is the terminal constitutional authority.

**A-series (Architectural Derivation):** A0 through A-n derive the logical architecture required to realize the constitutional specification. A0 is the first and foundational A-series document. It derives the complete runtime architecture. Subsequent A-series documents may derive sub-architectures for specific architectural domains, but none may contradict or extend the runtime boundaries established here.

**R-series (Runtime Specifications):** R1 through R16 (one per runtime) specify the internal logic, state, invariants, and interaction protocols of each runtime defined in A0. R-series documents derive their constitutional scope entirely from A0. An R-series document specifies a runtime; it does not define one.

**I-series (Implementation Specifications):** I-series documents specify how each runtime is realized in technology. They are fully subordinate to R-series and, through R-series, to A0 and the D-series. Implementation decisions have no constitutional standing.

A0 occupies the pivot position: it is the first document that makes architectural determinations (as opposed to constitutional specifications), and it is the last document that operates at full constitutional authority without implementation constraint.

### 1.2 What This Document Is

This document is a complete, normative derivation of the logical runtimes required for a constitutionally compliant APEX civilization. Specifically, it:

1. Identifies all candidate logical units from the constitutional stack
2. Determines, for each candidate, whether it constitutes a distinct runtime, a capability within a runtime, or a concept operating below the logical architecture level
3. Specifies each runtime's constitutional purpose, authority, responsibilities, owned objects, consumed objects, produced objects, inputs, outputs, lifecycle responsibilities, state responsibilities, invariants, dependencies, dependents, authority boundaries, failure responsibilities, audit responsibilities, and interaction contracts
4. Derives the complete runtime dependency graph, information flow graph, and authority relationship graph
5. Derives the complete runtime execution order from external signal to constitutional reflection
6. Identifies every constitutional enforcement point and every audit point in the architecture
7. Audits the complete architecture against D-2 through D8 to verify no constitutional requirement is lost, no constitutional category is redefined, and no constitutional authority is invented

### 1.3 What This Document Is Not

This document is not:

- A software architecture document. It contains no code, no APIs, no databases, no deployment topology, no technology choices.
- A runtime specification. That is the function of R-series documents. A0 defines what each runtime is and must do; R-series documents specify how each runtime internally operates.
- A domain specification. That is the function of D6 and its domain profiles. A0 maps domain requirements to runtimes; it does not respecify the domains.
- An implementation guide. I-series documents fulfill that function.
- An exhaustive enumeration of constitutional objects. D3, D4, D5, D6, D7, and D8 establish constitutional object types. A0 identifies which runtimes own, consume, and produce them.
- A planning document. A0 contains no timelines, phases, or sequencing of construction. D8 Part 10 specifies implementation phases; A0 is the architectural foundation those phases build upon.

### 1.4 Derivation Methodology

Every runtime in this architecture is derived by the following method:

**Step 1 — Constitutional Requirement Identification:** Identify the specific constitutional requirement from D-2 through D8 that necessitates a distinct logical unit.

**Step 2 — Independence Test:** Determine whether the requirement can be fulfilled by an existing runtime or whether it requires a distinct logical actor. A requirement necessitates a distinct runtime if and only if:
- (a) It has independent state that cannot be owned by another runtime without violating a constitutional boundary; OR
- (b) It has independent authority that cannot be held by another runtime without violating the authority separation requirements of D6 Part 4 or D8 INV-3; OR
- (c) It performs a constitutional role that is explicitly separated from other roles in the constitutional stack; OR
- (d) Its independence from other runtimes is constitutionally mandated (as with RT-04 Audit Runtime per D6 AIR-5).

**Step 3 — Boundary Determination:** Determine the runtime's boundaries by identifying what it owns, what it consumes from other runtimes, and what it produces for other runtimes. Boundaries are determined by constitutional object ownership, not by operational convenience.

**Step 4 — Dependency Derivation:** Determine the runtime's dependencies by identifying which other runtimes must have already operated before this runtime can fulfill its responsibilities. Dependencies are constitutional, not technical.

**Step 5 — Constitutional Citation:** Cite the specific constitutional provisions (D-series sections, axioms, gates, invariants, principles) that authorize the runtime's existence, define its responsibilities, and establish its boundaries.

### 1.5 Runtime Identification Criteria

A logical unit qualifies as a distinct runtime in A0 if and only if it satisfies at least one of the following criteria:

**Criterion R-1 (Independent Constitutional State):** The unit must maintain constitutional state that cannot be collapsed into another unit's state without losing a constitutionally mandated distinction.

**Criterion R-2 (Independent Constitutional Authority):** The unit must hold authority that cannot be co-located with another unit's authority without violating the constitutional authority separation requirements of D6 Part 4 (AIR-1 through AIR-5) or D8 INV-3.

**Criterion R-3 (Explicitly Separated Role):** The constitutional stack explicitly identifies the unit as a distinct actor, process, or capacity that must operate independently.

**Criterion R-4 (Mandated Independence):** The unit's independence from specific other units is constitutionally mandated (not merely architecturally convenient).

A logical unit does NOT qualify as a distinct runtime if it is:
- A constitutional object type (owned by a runtime, not itself a runtime)
- A capability or operation performed by a runtime (part of a runtime's responsibilities, not a runtime itself)
- An implementation concern (scheduling, communication, synchronization, versioning — these are realized within runtimes, not constituted as runtimes)
- A concept that spans multiple runtimes without independent state or authority (such as "projection," which is executed by RT-08 for inbound and RT-13 for outbound)

### 5.2 Constitutional Infrastructure Layer (RT-01 to RT-04)

This layer provides the foundational constitutional services required by every other runtime. It has no dependents within the layer except that RT-02 depends on RT-01 and RT-03 depends on RT-01 and RT-02. RT-04 is architecturally unique: it depends on RT-01, RT-03, and RT-05 for reading access, but is not processed through RT-03 for its own operations.

The constitutional significance of this layer is that it constitutes the enforcement substrate: without RT-01 (identity), no actor can be recognized; without RT-02 (authority), no operation can be authorized; without RT-03 (kernel), no operation can be admitted to the fabric; without RT-04 (audit), constitutional compliance cannot be independently verified.

The layer boundary is defined by the constitutional independence of these four runtimes from all operational concerns above them. They govern; they do not produce epistemic products or decisions.

### 5.3 Reality Fabric Layer (RT-05 to RT-07)

This layer constitutes the governed environment for all constitutional activity. RT-05 holds the graph; RT-06 evaluates its coherence; RT-07 persists its history. These three runtimes together implement the entire constitutional specification for the Reality Fabric (D3) and the Memory capacity (D-2 §XIII, D6 DOM-000004).

The constitutional significance of this layer is that it is the durable substrate of civilization truth: what the civilization knows, has decided, has done, and what happened as a result — all of it is held in this layer. The epistemic chain produces objects; the Reality Fabric layer holds them permanently.

### 5.4 Epistemic Chain Layer (RT-08 to RT-11)

This layer realizes the complete D3 Epistemic Chain from external observation to civilizational understanding. RT-08 opens the Observation Boundary; RT-09 forms epistemic products; RT-10 produces domain understanding; RT-11 synthesizes civilization-level understanding and deliberation.

The constitutional significance of this layer is that it is the only path from external reality to civilizational decision. Constitutional requirement: every CivilizationalDecision must be grounded in a CUM produced by RT-11 from Domain Understanding Models produced by RT-10 from Knowledge States produced by RT-09 from Observation Records produced by RT-08 from observations of external reality. No shortcuts through this chain are constitutionally permissible (D8 CLI-1: no stage omission).

### 5.5 Decision and Action Layer (RT-12 to RT-13)

This layer constitutes the constitutional act of decision and the constitutional act of projection. RT-12 forms CivilizationalDecisions; RT-13 projects them into external reality. Together they realize D7 Part 5 (decision requirements) and D5 Part 4 (Action Projection Lifecycle).

The constitutional significance of this layer is that it is where civilization agency is exercised. Every action in external reality traces through this layer. The constitutional obligation of irreversibility classification (D5 PI-8) is enforced here. Every authority to act passes through RT-02's validation before RT-13 crosses the Projection Boundary.

### 5.6 Feedback Layer (RT-14)

This layer constitutes a single runtime closing the Constitutional Loop. RT-14 is architecturally essential: without it, the civilization acts but never learns from those actions in a constitutionally governed manner. D8 INV-6 (Feedback Requirement) and D8 CLI-2 (No Constitutional Loop short-circuit) are both enforced by RT-14.

The constitutional significance of this layer is that it prevents civilization from becoming a one-directional actor — projecting into external reality without revising understanding based on what happens. RT-14 is the operational realization of the Reality Alignment Principle (D-2: all knowledge and action must pursue increasing alignment with reality; misalignment is the primary risk).

### 5.7 Domain Layer (RT-15 x12)

This layer realizes the twelve civilization domains of D6. It is architecturally unusual in that it contains twelve instances of a single archetype. The Domain Layer is both a consumer of constitutional infrastructure (RT-01, RT-02, RT-03, RT-07) and of epistemic products (RT-09, RT-10), and a producer of Domain Understanding Models that feed RT-11.

The constitutional significance of this layer is that it constitutes the civil structure of the civilization — the twelve bounded areas of governance through which all civilizational activity is organized, governed, and accounted for. Without this layer, APEX would have no constitutional structure for its activities; it would be a general-purpose epistemic engine without civilizational form.

### 5.8 Constitutional Maintenance Layer (RT-16)

This layer constitutes the civilization's capacity for legitimate constitutional self-modification. RT-16 is event-driven and depends on RT-11 (deliberation), RT-04 (Preservation Audit), and founding-level human authorization.

The constitutional significance of this layer is that it operationalizes the Forbidden Assumption from D-2: civilization cannot govern its own evolution without human oversight. RT-16 is the mechanism that ensures every constitutional change requires deliberation, independent audit, and founding-level human authorization. No runtime and no constitutional actor can modify the constitutional stack except through RT-16.
