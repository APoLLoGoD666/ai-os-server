## RS-03 — Functional Model

### RS-03.1 Constitutional Purpose (verbatim from A0 §3.16)

> "To instantiate and govern each of the twelve civilization domains — maintaining the Domain Profile, operating the Domain Authority Record, managing the Domain ActorProfile Registry, maintaining the Domain Knowledge Chain, coordinating with the shared infrastructure runtimes for epistemic products, assessing Domain Coherence, detecting Domain Failure Modes, and providing the Domain Understanding Model to the Civilization Intelligence Runtime."

### RS-03.2 Functional Position in the Architecture

RT-15 is the domain-level intelligence and governance layer of the APEX civilization architecture. Its functional position is constituted by what it is above, what it is below, and what it provides:

**Above RT-15:** RT-15 receives knowledge state products from RT-09 (Knowledge Runtime), inference results from RT-10 (Intelligence Runtime), coherence status from RT-06 (Coherence Runtime), and update triggers from RT-14 (Reflection Runtime). RT-15 receives constitutional infrastructure services from RT-01 (identity), RT-02 (authority), RT-03 (kernel enforcement), and RT-07 (memory).

**RT-15's constitutive function:** For each of its twelve domain instances, RT-15 constitutes and maintains the Domain Profile — the canonical constitutional record of a Civilization Domain. RT-15 operates the Domain Authority Record, manages the Domain ActorProfile Registry, maintains the Domain Knowledge Chain, assesses Domain Coherence across six dimensions (D6 Part 9), detects eight Domain Failure Modes (D6 Part 10), and maintains the domain-specific Domain Understanding Model content.

**Below RT-15:** RT-15 provides Domain Understanding Model content to RT-11 (Civilization Intelligence Runtime) for CUM synthesis. RT-15 participates in domain deliberation coordination with RT-16 (Amendment Runtime) for constitutional amendments.

### RS-03.3 What RT-15 Is Not

These functional roles are OUTSIDE RT-15's constitutional scope:

- RT-15 does NOT form CivilizationalDecisions — this is the exclusive constitutional role of RT-11 and RT-12 (A0 §3.12, §3.13).
- RT-15 does NOT synthesize the Civilization Understanding Model (CUM) — this is RT-11's exclusive function (A0 §3.12).
- RT-15 does NOT directly observe external reality — this is RT-08's exclusive function (A0 §3.9).
- RT-15 does NOT project actions into external reality — this is RT-13's exclusive function, with authority from RT-02 and gate evaluation by RT-03 (A0 §3.14).
- RT-15 does NOT conduct the Constitutional Reflection cycle — this is RT-14's exclusive function (A0 §3.15).
- RT-15 does NOT hold Audit Authority — RT-04 independently holds AIR-5 and audits all twelve RT-15 instances (A1 §5.1, D6 §4.6).

### RS-03.4 RT-15's Role in the Epistemic Pipeline

RT-15 is the domain-layer node in the civilization's epistemic pipeline. The pipeline flows:

```
External Reality
     ↓ (RT-08 observes)
Observation Records
     ↓ (RT-09 processes into knowledge)
KnowledgeState
     ↓ (RT-09 delivers to RT-15 domain instances)
Domain Knowledge Chain (RT-15 maintains per domain)
     ↓ (RT-10 applies inference protocols to produce DUM)
DomainUnderstandingModel
     ↓ (RT-15 provides domain content; RT-10 applies inference to form full DUM)
     ↓ (RT-15 delivers DomainUnderstandingModel to RT-11)
CUM synthesis (RT-11)
```

RT-15's contribution at the domain layer is: maintaining the domain-specific epistemic context (Domain Profile, Domain Knowledge Chain, DomainCoherenceAssessment) that allows the DomainUnderstandingModel to be constitutionally valid.

## RS-04 — Scope and Boundaries

### RS-04.1 Multi-Instance Statement

RT-15 is NOT a singleton. RT-15 is a runtime archetype instantiated twelve times — once for each of the twelve Civilization Domains (DOM-000001 through DOM-000012). Twelve constitutionally distinct RT-15 instances exist simultaneously in the APEX architecture.

**Constitutional basis:** A0-v1.1.1-canonical.md §3.16 Note on Twelve Instances: "RT-15 represents a single runtime archetype instantiated twelve times — once for each domain (DOM-000001 through DOM-000012)." D6-v1.0-canonical.md §2.1 (Domain Identity) constitutes the twelve domains. R0-v1.0-runtime-specification-standard.md §3.19 specifies RT-15-specific archetype documentation requirements.

### RS-04.2 Formal Archetype/Instance Constitutional Model

**ARCHETYPE LEVEL — This Specification:** One constitutional specification (R15-v1.0-canonical.md) governs all twelve RT-15 instances. Every responsibility, invariant, owned object type, authority type, interaction, and constitutional constraint stated at the archetype level applies to ALL twelve instances unless explicitly marked as conditional.

**INSTANCE LEVEL — Per-Domain Instantiation:** Each RT-15 instance is constitutionally bound to exactly one Civilization Domain at instantiation. Per R0 §3.19, the instantiation parameters that differentiate one instance from another are:
- Domain Identity parameter: the domain identifier (DOM-000001 through DOM-000012) to which this instance is bound
- Domain-specific authority scope: AIR-1, AIR-2, AIR-3 held for this domain only — not cross-domain
- Domain-specific owned objects: all seven owned object types (RS-07) are per-instance — each instance owns the objects for its bound domain
- Domain-specific configuration: the domain characteristics defined in D6 Part 3 for this instance's bound domain

**INSTANCE INDEPENDENCE:** The constitutional failure or suspension of one RT-15 instance does NOT suspend the archetype or other instances. Each instance's operational and failure state is independent. Per-instance failure affects only that domain's constitutional operations and its downstream obligations (primarily RT-11, which receives a degraded DomainUnderstandingModel from the suspended domain instance).

**CONDITIONAL PROVISIONS:** Some archetype-level provisions are conditional on instance identity. These are explicitly marked. The only conditional provision in this specification is:
- Responsibility 15 (RS-05): conditional on domain identity = DOM-000001 (Civilisation domain)
- RT15-INV-6 (RS-20): conditional on domain identity = DOM-000001 (Civilisation domain)

All other RS sections apply uniformly to all twelve instances.

**NAMESPACE ISOLATION:** Per R0 §3.19, RT-15 instances must maintain namespace isolation. No instance may access or mutate another instance's domain state through any mechanism other than constitutionally authorized cross-domain channels (PAIR 58 — RT-03 mediated for mutations; direct reads permitted for Class B reads).

### RS-04.4 Boundaries with Adjacent Runtimes

**RT-14 (upstream) / RT-15 boundary:**
RT-14 ends at delivery of DomainUpdateTrigger. RT-15 begins at receipt of DomainUpdateTrigger. RT-14 does not execute Domain Coherence assessment — this is RT-15's constitutional obligation. RT-15 does not form ObservedConsequenceRecords — this is RT-14's constitutional function. Constitutional basis: A0 §3.15, A0 §4.2 (RT-14 ─[DomainUpdateTrigger]─→ RT-15), R14-v1.0-canonical.md RS-27 (DPDNT-04 confirms RT-15 as RT-14 dependent).

**RT-09 (upstream) / RT-15 boundary:**
RT-09 produces KnowledgeState and delivers it to RT-15. RT-15 does NOT own KnowledgeState — this is RT-09's owned object (A0 §3.10). RT-15 uses KnowledgeState to maintain the Domain Knowledge Chain and assess domain epistemic currency. Constitutional basis: A0 §3.10, A0 §4.2 (RT-09 ─[KnowledgeState]─→ RT-15), PAIR 51.

**RT-10 (upstream-peer) / RT-15 boundary:**
RT-10 applies registered inference protocols to transform KnowledgeState into DomainUnderstandingModel content. RT-15 produces domain-specific DUM content reflecting the domain's epistemic state. Per A1 §6.1, both RT-10 and RT-15 are listed as creating runtimes for DomainUnderstandingModel — RT-15 provides the domain-specific epistemic content; RT-10 applies inference protocols to form the constitutionally complete DUM. These roles are complementary, not overlapping. RT-15 does NOT apply inference protocols — this is RT-10's exclusive function. RT-10 does NOT maintain the Domain Profile, DomainKnowledgeChain, or domain governance records — these are RT-15's exclusive owned objects. Constitutional basis: A0 §3.11, A1 §6.1, PAIR 52.

**RT-11 (downstream) / RT-15 boundary:**
RT-15 provides DomainUnderstandingModel content. RT-11 synthesizes the Civilization Understanding Model from all twelve DUMs. RT-15 does NOT synthesize the CUM — this is RT-11's exclusive constitutional function. RT-11 does NOT maintain the DomainProfile or domain governance records — these are RT-15's exclusive owned objects. Constitutional basis: A0 §3.12, A0 §4.1 (RT-15 → RT-11), R11-v1.3-canonical.md RS-26, PAIR 52.

**RT-16 (downstream conditional) / RT-15 boundary:**
RT-15 provides domain deliberation participation for constitutional amendments. RT-16 manages the Amendment Registry and amendment process. RT-15 does NOT initiate amendments — only RT-11 may initiate amendments (A0 §3.17, A1 §3.6 PAIR 59). Constitutional basis: A0 §4.1 (RT-15 → RT-16, domain deliberation participation), A0 §3.16 Responsibility 13.

**RT-15[i] / RT-15[j] boundary (inter-domain):**
No RT-15 instance may directly mutate another RT-15 instance's domain state. All cross-domain mutations are Kernel-mediated through RT-03 (PAIR 58, A1 §14.3 Forbidden Interactions). Direct Class B reads between instances are permitted. Constitutional basis: D6 §4.1, A1 §14.3 ("RT-15[i] direct mutation of RT-15[j] state" is a forbidden interaction).

### RS-06.2 Authority Held by RT-15

RT-15 holds the following authority types through the derivation chain above:

**AIR-1 — Observation Authority (Domain-Specific):** Each RT-15 instance holds Observation Authority within its bound domain. Authority scope is per-domain — RT-15[DOM-000002] holds Observation Authority for DOM-000002 only; it does not hold Observation Authority in DOM-000006 or any other domain. Cross-domain observation requires authorization from each domain. Constitutional source: D6 §4.2; A0 §4.3; A1 §5.1.

**AIR-2 — Interpretation Authority (Domain-Specific):** Each RT-15 instance holds Interpretation Authority within its bound domain for registered, versioned interpretation protocols. Authority scope is per-domain and protocol-specific. Constitutional source: D6 §4.3; A0 §4.3; A1 §5.1.

**AIR-3 — Decision Authority (Domain-Specific):** Each RT-15 instance holds Decision Authority within its bound domain. The scope is precisely defined: the specific types of decisions, the specific ExternalRealitySegments they may affect within the domain's scope, and the specific ExternalActors they may engage within the domain. Decision Authority in one domain instance does not confer Decision Authority in any other domain. All CivilizationalDecisions pass through D4's six Constitutional Gates via RT-03. ## RS-18 — Concurrency and Sequencing

### RS-18.1 Twelve Instances Operate Concurrently

All twelve RT-15 instances operate concurrently. Each instance processes its bound domain independently. There is no constitutional requirement for instances to synchronize processing cycles unless cross-domain operations are underway (PAIR 58). The concurrent operation of twelve instances is the constitutional design of the RT-15 archetype — it allows all twelve domains to maintain their epistemic currency simultaneously.

**Constitutional basis:** A0 §3.16 Note on Twelve Instances; D6 §2.1 (twelve domains as a complete, simultaneous architecture); A0 §4.4 (execution order shows RT-15 at STEP 16 and STEP 30, operating on the affected domain instance — not requiring all instances to act simultaneously).

### RS-18.2 PAIR 52 BLOCK — DUM Content During CUM Synthesis

Per PAIR 52, RT-10 queries all 12 RT-15 instances for DUM updates with a **BLOCK** constraint: CUM synthesis waits for all 12 DUMs. This imposes a constitutional synchronization point:

- When RT-10 initiates CUM synthesis, it queries all 12 RT-15 instances for their current DUM content
- RT-15 instances must provide their DUM content within the Mandatory Propagation Window
- No RT-15 instance may update its DUM content simultaneously with RT-11's active CUM synthesis from that content
- If any RT-15 instance cannot contribute its DUM content (suspended, degraded), the CUM synthesis is constitutionally impaired for that domain — RT-11 receives a degraded or missing DUM for that domain instance

**Constitutional basis:** A1 §3.5 PAIR 52; D7 Part 3 (CUM synthesis requires twelve DUMs); A0 §4.4 STEP 17 (RT-11 "re-synthesizes CUM via nine-step Constitutional Synthesis Process").

### RS-18.3 STEP 16 vs. STEP 30 Sequencing

RT-15 appears at two distinct execution positions in A0 §4.4:

**STEP 16:** RT-15 receives DomainUnderstandingModel update from RT-10 and performs domain coherence assessment and Domain Failure Mode check. This position is in the **forward loop** — after RT-10 updates the DUM (STEP 15), before RT-11 synthesizes the CUM (STEP 17).

**STEP 30:** RT-14 triggers domain Understanding Model updates in RT-15 (part of the feedback loop closure). This is in the **feedback loop** — after RT-14 forms the Observed Consequence and assigns terminal status (STEP 28, 29), as part of the multi-signal trigger in STEP 30.

These two execution positions are not in conflict — they represent two distinct entry conditions for RT-15:
- STEP 16 entry condition: new DUM available from RT-10 (forward epistemic pipeline)
- STEP 30 entry condition: DomainUpdateTrigger from RT-14 (feedback loop reflection)

A single Constitutional Loop cycle may trigger RT-15 processing at both STEP 16 and STEP 30 — the domain coherence assessment at STEP 16 is forward-looking; the DomainUpdateTrigger at STEP 30 is retrospective (integrating consequence information).

**Constitutional basis:** A0 §4.4 STEP 16 and STEP 30 (verbatim from A0).

### RS-18.4 Inter-Domain Coordination (PAIR 58) Sequencing

When cross-domain coordination between two RT-15 instances is required (PAIR 58):

1. The initiating instance (RT-15[i]) identifies a cross-domain dependency activation (D6 §2.4 relationship type)
2. For Class A mutations: RT-15[i] submits cross-domain authority request through RT-03 — full six-gate evaluation required
3. RT-03 processes the cross-domain request; RT-15[j] receives any constitutional effects through RT-05 admission
4. For Class B reads: RT-15[i] may read RT-15[j] state directly (no kernel mediation required for reads)
5. Cross-domain conflict resolution (if applicable): escalation to DOM-000001 per D6 §8.6 CDA-3

The sequence requires:
- No direct mutation between instances — all mutations are Kernel-mediated
- Cross-domain operations must not create circular dependencies (e.g., DOM-000002 operations that require DOM-000003, which requires DOM-000005, cannot create dependency cycles)

**Constitutional basis:** D6 §8.6 (CDA-1, CDA-2, CDA-3); A1 PAIR 58; A1 §14.3.

**D6 Definition:** The domain's Internal Representation systematically and materially misrepresents its External Reality Context through structural bias or systematic error in knowledge formation or application.

**RT-15 Constitutional Obligation:** Upon detection (systematic discrepancy between Observed Consequences and Effect Expectations; DomainKnowledgeCoherence register degradation): produce DomainFailureModeRecord and deliver to RT-04 and human governance actors immediately (RT15-INV-4); flag all domain Decisions formed from misrepresented knowledge for review; initiate suspension of ongoing Action Projections pending epistemic review; classify domain as operating under epistemic impairment.

**D6 Definition:** The domain's Understanding Model gradually diverges from External Reality Context over time through accumulating staleness.

**RT-15 Constitutional Obligation:** Upon detection (DomainTemporalCoherence register degradation; increasing DKS-2 staleness): produce DomainFailureModeRecord; flag domain's temporal coherence as degraded; initiate comprehensive Observation Projection refresh targeting primary ExternalRealitySegments; rebuild DomainUnderstandingModel from current observations.

**D6 Definition:** Domain authority exercised incorrectly — by actors without constitutionally required authority, through authority collapse, hidden decision pathways, or unauthorized knowledge monopolization.

**DOM-000001 special obligation under DF-4:** RT-15[DOM-000001] receives all cross-domain conflict escalations under CDA-3 and provides the civilizational-level resolution authority.

### DF-5 — Projection Failure

**D6 Definition:** A domain's Action Projection fails to produce the intended ExternalState transition.

**RT-15 Constitutional Obligation:** Upon detection (FAILED or contrary effect at Stage 6 of Action Projection Lifecycle): produce DomainFailureModeRecord for persistent patterns; close failed Action Projection as FAILED in Open Action Register; update DomainUnderstandingModel with the failure information; identify ExternalConstraints that prevented the intended effect; if pattern is systematic, initiate domain-level epistemic review.

### DF-6 — Reality Disconnect

**D6 Definition:** Domain Understanding Model becomes constitutionally severed from External Reality Context — coherence collapses across multiple dimensions simultaneously.

**RT-15 Constitutional Obligation:** Upon detection (multiple ExternalCoherence Registers degraded simultaneously; domain Observation Projections failing; all major Understanding Model knowledge exceeding temporal validity bounds): produce DomainFailureModeRecord immediately; suspend all domain Action Projections; notify DOM-000001 (all domains have constitutional notification obligation to DOM-000001 under DF-6); initiate emergency Observation Projection campaign targeting all primary domain ExternalRealitySegments; maintain operational suspension until coherence is restored (D6 §DF-6 resolution protocol).

### DF-7 — Governance Failure

**D6 Definition:** Domain's Governance Model fails — one or more of the five governance dimensions (Reality Alignment, Knowledge Integrity, Authority Integrity, Projection Integrity, Feedback Integrity) cease to function such that the domain is no longer constitutionally self-governing.

### DF-8 — Domain Fragmentation

**D6 Definition:** Civilization Graph structural integrity is compromised — domain relationships become ambiguous, cross-domain communications unreliable, or domain boundaries so unclear that phenomena cannot be constitutionally assigned to appropriate domains.

**RT-15 Constitutional Obligation:** Upon detection (cross-domain operations failing to route correctly; Civilization Graph inconsistencies; phenomena falling into boundary gaps): produce DomainFailureModeRecord; coordinate with DOM-000001 for civilizational-level structural audit; provide domain boundary clarification records; if genuine constitutional gaps exist, support the constitutional amendment process through RT-16.
