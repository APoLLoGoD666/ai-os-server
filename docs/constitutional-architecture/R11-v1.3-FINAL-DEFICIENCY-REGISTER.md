### FAA-11RF3-001

| Field | Value |
|---|---|
| **Deficiency ID** | FAA-11RF3-001 |
| **Class** | III — Minor Defect |
| **Section** | RS-11 (Managed State) |
| **Line** | 366 |
| **Constitutional Basis** | A0 §3.12 Owned Objects; A0 §3.13 Owned Objects |

**Description:**

The RS-11 state variable table describes `last_decision_ref` as: "Reference to most recent CivilizationalDecision — Updated on delivery."

**Evidence:**

RS-11, Managed State table, row for `last_decision_ref`:
- Type: Reference
- Description: "Reference to most recent CivilizationalDecision"
- Lifecycle: "Updated on delivery"

RS-12 Process 3 Step 12: "Update `last_decision_ref` and clear `deliberation_active`" — this step occurs after Step 11: "Deliver to RT-12 (PAIR 40, DLVR permission)."

**Constitutional Analysis:**

At the moment `last_decision_ref` is updated (Step 12 of Process 3), RT-11 has delivered a CivilizationalDecisionProposal to RT-12. RT-12 has not yet formed the CivilizationalDecision — that object is RT-12's exclusive output per A0 §3.13 Owned Objects. The state variable label "most recent CivilizationalDecision" implies RT-11 is tracking RT-12's formed object (CivilizationalDecision), which is constitutionally owned by RT-12, not RT-11.

The correct reference at this stage is the CivilizationalDecisionProposal that RT-11 has just delivered. The label should read "Reference to most recent CivilizationalDecisionProposal delivered to RT-12" to accurately reflect what RT-11 can constitutionally know at the point of update.

**Impact:**

This constitutes an imprecise attribution — the state variable description implies RT-11 state includes a reference to an RT-12-owned object (CivilizationalDecision) rather than RT-11's own produced object (CivilizationalDecisionProposal). It does not constitute a Class I defect because RT-11 does not claim to manage, own, or produce the CivilizationalDecision object in any definitive statement; the imprecision is in the state variable label only.

**Remediation:**

Correct `last_decision_ref` description to "Reference to most recent CivilizationalDecisionProposal delivered to RT-12" and update lifecycle note to "Updated on Proposal delivery to RT-12."

### FAA-11RF3-002

| Field | Value |
|---|---|
| **Deficiency ID** | FAA-11RF3-002 |
| **Class** | III — Minor Defect |
| **Section** | RS-11 (Managed State) |
| **Line** | 374 |
| **Constitutional Basis** | A0 §3.12 Produced Objects; A0 §3.13 Produced Objects |

**Description:**

The RS-11 State Persistence statement contains the phrase "State changes that produce CivilizationalDecisions or modify CUM version are Class A operations."

**Evidence:**

RS-11, State Persistence paragraph (full text): "All state must be persisted through RT-03 kernel mediation for Class A state transitions. State changes that produce CivilizationalDecisions or modify CUM version are Class A operations."

**Constitutional Analysis:**

A0 §3.12 Produced Constitutional Objects lists: "CivilizationUnderstandingModel (CUM); DeliberationRecord; CivilizationalDecisionProposal (for RT-12); StrategicPlan; CausalModelRevisionRecord." CivilizationalDecision is NOT in RT-11's produced objects list. CivilizationalDecision is produced by RT-12 (A0 §3.13 Produced Constitutional Objects).

The phrase "State changes that produce CivilizationalDecisions" in the context of RT-11's internal state persistence attributes CivilizationalDecision production to RT-11's state operations. This is constitutionally inaccurate. RT-11's state changes produce CivilizationalDecisionProposals (not CivilizationalDecisions). RT-12 forms CivilizationalDecisions from RT-11's proposals.

**Impact:**

This constitutes a minor constitutional imprecision. The broader document (RS-07, RS-09, RS-10 Item 3, RS-35) is unambiguous that RT-11 does not produce CivilizationalDecisions. The imprecision here does not rise to Class I because it is isolated in a state persistence classification statement and contradicted by explicit boundary statements elsewhere. However, the imprecision is constitutionally meaningful because it appears in a normative section (RS-11) and attributes an incorrect object type to RT-11's state operations.

**Remediation:**

Correct to "State changes that produce CivilizationalDecisionProposals or modify CUM version are Class A operations."

### FAA-11RF3-004

| Field | Value |
|---|---|
| **Deficiency ID** | FAA-11RF3-004 |
| **Class** | IV — Editorial / Traceability |
| **Section** | RS-06 (Authority) |
| **Lines** | 163-164 |
| **Constitutional Basis** | D6 §4.4 (Decision Authority); R0 CERT-03 |

**Description:**

RS-06 cites the authority derivation chain as "D-6 §4.1 → D-6 §4.2–4.4 → A0-v1.1.1 §4.3 → A1-v1.2 §5.1." The section range §4.2–4.4 covers Observation Authority (§4.2), Interpretation Authority (§4.3), and Decision Authority (§4.4). RT-11 holds only Decision Authority, making §4.4 the exclusively relevant section. The citation is broader than necessary, including §4.2 and §4.3 which are not the basis for RT-11's held authority.

**Impact:** Advisory only. The citation is not wrong (§4.4 is included in the range cited, and §4.1 correctly introduces the five authority types). The breadth does not affect the correctness of the authority claim. No certification impact.

**Remediation (advisory):** Narrow citation to "D-6 §4.1 (five authority types introduced) → D-6 §4.4 (Decision Authority defined) → A0-v1.1.1 §4.3 → A1-v1.2 §5.1" for precision.

### FAA-11RF3-005

| Field | Value |
|---|---|
| **Deficiency ID** | FAA-11RF3-005 |
| **Class** | IV — Editorial / Traceability |
| **Section** | RS-29 (Constitutional Loop Participation) |
| **Line** | 1122 |
| **Constitutional Basis** | A1 §15.2 (Runtime-to-Loop-Phase Mapping) |

**Description:**

RS-29 assigns RT-11 a "SUPPORTING" role in the Understanding phase (Phase 4) with the activity note "Receives DUMs from RT-10 (PAIR 32)."

A1 §15.2 shows the Understanding phase with Primary Runtime: RT-10 and Supporting Runtimes: RT-15, RT-09. RT-11 does not appear in either the Primary or Supporting column for the Understanding phase in A1 §15.2.

RS-29 is characterizing RT-11's factual activity at the Understanding phase (it does receive DUMs from RT-10 during this phase) but attributes to it a "SUPPORTING" role designation that is not present in A1 §15.2's Supporting Runtimes column for that phase.

**Impact:** Advisory only. The primary phase assignments (Deliberation PRIMARY, Decision PRIMARY, Updated Understanding PRIMARY) are all correct. The Understanding phase SUPPORTING label is an editorial addition not directly supported by A1 §15.2's column assignments. No certification impact.

**Remediation (advisory):** Change RS-29 Understanding phase RT-11 role from "SUPPORTING" to "CONSUMER" or "NONE (receives DUMs as phase boundary)" to avoid implying A1 §15.2 designates RT-11 as a Supporting runtime for this phase.
