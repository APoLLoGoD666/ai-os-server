[FIND-001] Class III
Location: RS-06 §6.1 — Authority Class
Constitutional basis: R0 §3.5 (AIR-1 through AIR-5 = authority type numbering); D6 §4.7 (AIR-1 through AIR-5 = Authority Integrity Rule numbering)
Finding: The heading "**AIR-1 Authority Integrity Rule (D6 §4.7 AIR-3)**" conflates two distinct "AIR" numbering systems that coexist in the constitutional architecture. R0 §3.5 defines AIR-1 = Observation Authority, AIR-2 = Interpretation Authority, AIR-3 = Decision Authority, AIR-4 = Projection Authority, AIR-5 = Audit Authority (the five authority types). D6 §4.7 defines a separate set of Authority Integrity Rules numbered AIR-1 through AIR-5 (AIR-1 = Authority Separation, AIR-2 = No Unauthorized Projection, AIR-3 = No Knowledge Monopolization, AIR-4 = No Hidden Decisions, AIR-5 = Audit Independence). The heading reads as if referencing a rule called "AIR-1 Authority Integrity Rule" (suggesting this is D6 §4.7 AIR-1 = Authority Separation), but the parenthetical "(D6 §4.7 AIR-3)" clarifies the intended source is D6 §4.7 AIR-3 (No Knowledge Monopolization). This creates a misleading heading. Compounding the issue: the immediately following "Authority Separation Principle" paragraph uses "AIR-3" in the R0 §3.5 sense (AIR-3 = Decision Authority — RT-12), creating an internal inconsistency within RS-06 §6.1 where "AIR-3" means two different things in two adjacent paragraphs.
Remediation: Revise the heading to eliminate the conflation. Replace "AIR-1 Authority Integrity Rule (D6 §4.7 AIR-3)" with a heading that is unambiguous — for example: "D6 §4.7 AIR-3 (No Knowledge Monopolization) — Observation/Interpretation Separation." Ensure all uses of "AIR-N" within RS-06 §6.1 consistently use either R0 §3.5 naming or D6 §4.7 naming with explicit disambiguation labels.
Certification impact: Non-blocking. The substantive constitutional content is correct — the correct D6 §4.7 AIR-3 rule is quoted verbatim and correctly applied. The authority types claimed (AIR-1 = Observation, AIR-4 = Projection) are correctly identified per R0 §3.5 and A1 §5.1. This is an editorial/traceability deficiency that does not affect constitutional substance.

[FIND-002] Class II
Location: RS-29 (Constitutional Loop Participation — Loop 2 description; CLI compliance claims), RS-31 (Phase Ownership table)
Constitutional basis: A1-v1.2 §15.2 (Runtime-to-Loop-Phase Mapping table)
Finding: R8 characterizes RT-08 as "Supporting runtime" for the "Observation of Consequence" phase (RS-29 Loop 2: "RT-08 position: Supporting runtime — responds to RT-14 trigger"; RS-31 table row: "Observation of Consequence | Supporting Runtime"). A1-v1.2 §15.2 contradicts this characterization. The §15.2 table row is: "Observation of Consequence | RT-14 → RT-08 | RT-07, RT-06." The Primary Runtime column contains "RT-14 → RT-08" — placing RT-08 in the Primary column, not the Supporting column. The Supporting Runtimes column for this phase contains "RT-07, RT-06" — not RT-08. R8 has misread or misapplied A1 §15.2: it has assigned RT-08 to the Supporting column when A1 §15.2 places RT-08 in the Primary column for this phase. R0 CERT-07 criterion states: "RS-29 exactly matches A1 §15.2 for this runtime." This mismatch causes CERT-07 to fail. The interpretation that RT-14 is primary and RT-08 is supporting is a reasonable functional interpretation of the sequence "RT-14 → RT-08" but is not what A1 §15.2 states — A1 §15.2 places the full sequence "RT-14 → RT-08" in the Primary column, indicating both runtimes are primary for this phase (in sequence), not one primary and one supporting.
Remediation: Revise RS-29 Loop 2 to state: "RT-08 position: Primary runtime (in sequence with RT-14) — RT-14 → RT-08 sequence constitutes the primary pathway for Observation of Consequence per A1-v1.2 §15.2." Revise RS-31 Phase Ownership table row "Observation of Consequence" from "Supporting Runtime" to "Primary Runtime (sequence with RT-14 — RT-14 → RT-08 per A1-v1.2 §15.2)." Update CERT-07 self-assessment accordingly.
Certification impact: Blocking — this finding directly causes CERT-07 (Loop Audit) to fail per the criterion "RS-29 exactly matches A1 §15.2 for this runtime." CERT-10 (Constitutional Preservation) is also affected because A1 §15.2 is not fully reflected in RS-29/RS-31. These two CERT failures constitute a material specification defect requiring remediation before unconditional certification.

[FIND-003] Class I
Location: RS-06 §6.2 (Authority Derivation Chain), RS-06 §6.4 (ADR-1 compliance statement)
Constitutional basis: R0 §2.2 ADR-1 ("The authority derivation path is mandatory: D6 → A0 → A1 → R0 → R1–R16"); R0 CERT-03 ("For every RS-06 authority: trace D6 type definition → A0 §4.3 instantiation → A1 §5.1 entry")
Finding: R8 RS-06 §6.2 states the authority derivation chain as: "D3 RF-A6 → D5 Part 3 → D6 §4.2/§4.5 → A0-v1.1.1 §3.9 → R0 → R8 v1.0." RS-06 §6.4 ADR-1 compliance states: "RT-08's AIR-1 authority is derived from D6 §4.2 → A0-v1.1.1 §3.9 → R0 → R8 v1.0. RT-08's AIR-4 authority is derived from D6 §4.5 → A0-v1.1.1 §3.9 → R0 → R8 v1.0." Neither derivation chain includes: (a) A0 §4.3 (the Authority Relationship Graph, which is the designated A0 authority instantiation point per CERT-03), or (b) A1 §5.1 (the Authority Type Distribution table, which is the A1 authority confirmation point per CERT-03). CERT-03 requires the trace "D6 type definition → A0 §4.3 instantiation → A1 §5.1 entry" for every RS-06 authority claim. The substantive content is verifiably correct — A1-v1.2 §5.1 explicitly confirms RT-08 holds AIR-1 (column: "Obs. Projection") and AIR-4 (column: "Inbound"). A0 §4.3 provides the general authority flow structure from which RT-08's authority is derivable (though A0 §4.3 uses descriptive labels rather than AIR-1/AIR-4 labels; A0 §3.9 Constitutional Authority cites D5 Part 3 and D3 RF-A6). The failure is a traceability and citation gap in the derivation chain, not a substantive constitutional error.
Remediation: Revise RS-06 §6.2 derivation chain to include A1 §5.1 as an explicit link: "D3 RF-A6 → D5 Part 3 → D6 §4.2/§4.5 → A0-v1.1.1 §3.9 [Constitutional Authority] → A0 §4.3 [Authority Relationship Graph] → A1-v1.2 §5.1 [Authority Type Distribution] → R0 → R8 v1.0." Revise RS-06 §6.4 ADR-1 compliance statement to include: "...A0 §4.3 and A1-v1.2 §5.1 confirm the authority assignment."
Certification impact: Non-blocking. The substantive authority is correct and independently verifiable from source documents. The deficiency is a traceability/citation completeness gap in the derivation chain specification. A1 §5.1 confirms the authority; it simply is not cited in RS-06 §6.2. CERT-03 is technically incomplete (missing A1 §5.1 citation), but the authority claim itself is not constitutionally erroneous. Classification is Class I (major defect) due to the mandatory nature of the CERT-03 trace requirement per R0.
