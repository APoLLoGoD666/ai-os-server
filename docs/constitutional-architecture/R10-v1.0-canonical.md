### RS-06 — Authority

**RS-06.1 Authority Types Held**

RT-10 holds exactly one authority type, instantiated through A0 §4.3 and confirmed by A1 §5.1.

**NOTE ON AIR NOMENCLATURE (FIND-001 lesson applied):** D6 uses "AIR-N" in two distinct senses. D6 §4.2–4.3 uses "AIR-N" to name authority **types** (five categories: Observation, Interpretation, Decision, Projection, Audit). D6 §4.7 uses "AIR-N" to name **Authority Integrity Rules** (structural governance rules: AIR-1 = Authority Separation, AIR-2 = No Unauthorized Projection, AIR-3 = No Knowledge Monopolization, AIR-4 = No Hidden Decisions, AIR-5 = Audit Independence). These are different content sharing the same notation. In this specification: "authority type AIR-N" always refers to D6 §4.2–4.3 types; "D6 §4.7 Authority Integrity Rule AIR-N (Rule Name)" always refers to D6 §4.7 rules. The two are never conflated.

**Authority type AIR-2 (Interpretation Authority):**
- Domain: Domain Understanding — the constitutional right to apply registered inference protocols to Knowledge States, transforming them into Domain Understanding Models
- D6 source: D6 §4.3 (authority type definition: "the constitutional right to apply registered interpretation protocols to Observation Records within a domain, transforming them into Evidence (D5 Part 3, Stage 4)"); applied to RT-10's Knowledge→Understanding transformation
- A0 instantiation: A0 §4.3 authority relationship graph — RT-10 holds authority type AIR-2 in the Domain Understanding domain, granted by RT-02
- A1 confirmation: A1 §5.1 authority type distribution table — RT-10 row: — | Domain Understanding | — | — | —

- D6 §4.3 obligations of authority type AIR-2 holders: (a) apply only registered, versioned inference protocols; (b) record which protocol version was applied; (c) not distort Knowledge in the direction of expected or desired results; (d) escalate interpretive disagreements rather than resolving them unilaterally

- Instances: 12 — one per each of the twelve civilization domains
- Creation conditions: RT-10 creates one Domain Understanding Model per domain by applying a registered InferenceProtocol to the Knowledge State for that domain (O10-01, O10-02). ### RS-23 — Audit Requirements

#### RS-23.1 RT-04 Audit Scope

RT-04 (Constitutional Audit Runtime) holds authority type AIR-5 (Audit Authority) over all RT-10 operations under D6 §3.4 and A1 §14.1. RT-04 audits the following RT-10 operations:

1. Every Domain Understanding Model Formation operation (RT10-PROC-01): provenance chain anchored to Knowledge Record ID(s); registered InferenceProtocol version recorded; uncertainty attributes preserved (RT10-INV-2); temporal validity metadata set (RT10-INV-4 precondition); DegradationFlag produced when DKS-3 or DKS-4 source
2. Every CUM Synthesis operation (RT10-PROC-04): twelve-domain currency check (RT10-STATE-04); CUM-1 through CUM-5 preconditions satisfied; CUM provenance anchored to all 12 DUM IDs + RT-10 synthesis operation ID; CUM submitted as Class A; ownership transfer to RT-11 on delivery (not claimed by RT-10)

4. Every UnderstandingDegradationFlag production (RT10-OBJ-03): triggered by DKS-3 or DKS-4 source Knowledge State; delivered to RT-06 and RT-11
5. Every Gate 4 EpistemicChainState provision (RT10-PROC-07): EpistemicChainState accuracy; understanding-stage conditions verified
6. All Domain Understanding Model transmissions to RT-11 (RT10-OUT-01) and RT-15 (RT10-OUT-02)
7. All CUM deliveries to RT-11 (RT10-OUT-05): ownership boundary respected (RT-10 does not claim CUM post-delivery)
8. All lifecycle state transitions (RT10-STATE-07)
9. All suspension events (RT10-LC-07) and resumption events (RT10-TRANS-10 through RT10-TRANS-12)
10. Rollback compliance (RC-1): RT-10 never initiates rollback; RT-10 correctly reverts on RT-03 directive
11. InferenceProtocol compliance: RT-10 applies only registered, versioned protocols (RT10-INV-3); RT-04 verifies protocol version recorded in every DUM provenance

#### RS-23.2 Observable Operations

Every RT10-PROC-NN internal process is observable to RT-04. RT-10 is constitutionally obligated to make the following observable per D6 §3.4:

- RT10-PROC-01 through RT10-PROC-07: process initiation, inputs consumed, outputs produced, completion or failure
- Every Class A submission to RT-03: object type (Domain Understanding Model or CUM), operation ID, provenance chain
- Every Class B signal: UnderstandingDegradationFlag content, domain, DKS source classification, recipient runtimes
- Every Gate 4 query response: EpistemicChainState content delivered
- Every DUM status transition: domain, from-status, to-status (CURRENT/DEGRADED/STALE), triggering Knowledge State DKS classification

#### RS-23.3 Observable State

RT-04 may inspect all RT-10 state variables at any time:

- RT10-STATE-01 (DomainUnderstandingModelRegistry): all twelve domain Domain Understanding Model entries, versions, DKS-source classification, protocol-IDs
- RT10-STATE-02 (InferenceProtocolRegistry): all registered protocols and versions
- RT10-STATE-03 (UnderstandingDegradationRegister): all degradation flag statuses per domain
- RT10-STATE-04 (DUMCurrencyTracker): twelve-domain currency status
- RT10-STATE-05 (CUMSynthesisState): current CUM synthesis lifecycle state
- RT10-STATE-06 (EpistemicChainStateCache): current understanding-stage epistemic chain state per domain
- RT10-STATE-07 (ActivationState): current operational state

RT-10 may not restrict RT-04 access to any of the above. Blocking RT-04 inspection is a constitutional violation (D6 §3.4; D8 PROH-4).

#### RS-23.4 Audit Records

Audit Records for RT-10 operations follow the format: RT04-AUD-RT10-NN where NN is a sequential identifier per audit cycle. Each Audit Record must contain: operation type, RT-10 operation ID, RT-10 lifecycle phase at time of audit, objects involved (by D8 §4.1 canonical type and ID), provenance chain status, invariant compliance status for RT10-INV-1 through RT10-INV-4, authority type validated (AIR-2), InferenceProtocol version applied, timestamp.

#### RS-23.5 Audit Trail Completeness Criterion

An audit trail for one RT-10 operation cycle is complete when: (a) RT04-AUD-RT10-NN exists for every RT10-PROC-NN execution in that cycle; (b) every Class A submission has a corresponding audit record showing gate outcomes; (c) every UnderstandingDegradationFlag production is documented; (d) provenance chain verification for all Domain Understanding Models produced is recorded; (e) InferenceProtocol version recorded for each DUM formation; (f) CUM ownership boundary documented (RT-10 produced; RT-11 owns on delivery).

#### RS-23.6 Audit Permanence

Audit Records for RT-10 are never rolled back, never deleted, and never modified after creation (A1 RC-3; A1 RC-4). When RT-03 initiates rollback of an RT-10 Domain Understanding Model or CUM, the Audit Records documenting both the original operation and the rollback event are both retained permanently.
