## PART 2 — INTERACTION ARCHITECTURE FOUNDATIONS

### 2.1 Interaction Categories

All runtime interactions are classified into one of two fundamental categories:

**Category I: Direct Interaction**  
Runtime A interacts with Runtime B without constitutional requirement to pass through RT-03. Direct interaction is permitted only when:
- The operation is Class B (Kernel Manifest type, as defined in D-4 §3.2), OR
- The interaction is RT-04 Audit Authority exercising AIR-5 (Audit Exception, constitutionally mandated independence), OR
- The interaction is RT-03 itself exercising its Gate authority over another runtime.

**Category II: Kernel-Mediated Interaction**  
Runtime A submits a Class A operation to RT-03. RT-03 applies all six gates. Upon admission, RT-03 propagates the operation to the fabric. Downstream runtimes receive the operation outcome through RT-03's commit sequence. No runtime may bypass this mediation for Class A operations.

**The Kernel Mediation Principle (KMP):**  
All Class A operations from any actor-runtime pass through RT-03 before admission to the Reality Fabric. This is not a design choice; it is a constitutional mandate derived from D-4 §2.1.

**The Audit Exception (AIR-5):**  
RT-04 (Constitutional Audit Runtime) exercises AIR-5 authority. RT-04 observes all operations including RT-03's operations without passing through RT-03 for its audit operations. RT-04 may never be gated by the entity it audits. This is derived from D-6 §3.4 and A0 §3.4.

### 2.2 Eight Interaction Properties

Every interaction between two runtimes is characterized by eight properties:

**P1 — Direction:** Unidirectional (A→B only) or Bidirectional (A↔B, meaning both A→B and B→A exist as distinct interactions).

**P2 — Authority Ownership:** Which runtime holds constitutional authority over the interaction. The authority-owning runtime determines whether the interaction proceeds.

**P3 — Mutation Ownership:** Which runtime may mutate objects as a result of the interaction. Mutation without ownership is a constitutional violation.

**P4 — Object Ownership:** Which runtime owns the objects transferred in the interaction. Ownership determines provenance anchor.

**P5 — Provenance Responsibility:** Which runtime must record the provenance chain for objects produced or transformed by the interaction.

**P6 — Temporal Responsibility:** Which runtime is responsible for temporal sequencing — ensuring the interaction occurs within its constitutionally required window.

**P7 — Blocking Behavior:** Whether the initiating runtime must halt and await completion (Blocking), may proceed without waiting (Non-Blocking), or must halt only if the result is negative (Conditional Block).

**P8 — Rollback Responsibility:** If the interaction produces an outcome that requires rollback, which runtime bears constitutional responsibility for executing rollback, and which runtime must confirm rollback completion.

### 2.3 Six Constitutional Constraints on Interactions

**CC-1 — No Orphan Object:** Any object produced by an interaction must have a constitutionally designated owner before the interaction completes. An object without an owner cannot be admitted to the Reality Fabric.

**CC-2 — No Unwitnessed Authority Exercise:** Any exercise of constitutional authority (AIR-1 through AIR-5) must be witnessed by RT-04. Authority exercised without audit witness is constitutionally void.

**CC-3 — No Circular Delegation:** No runtime may delegate authority to a runtime that directly or indirectly delegates authority back to the original runtime within the same operation. Delegation chains are acyclic within a single operation.

**CC-4 — No Temporal Inversion:** No runtime may act upon the consequence of an operation before that operation has been constitutionally admitted. The admission timestamp (Stage 8 of the 10-Stage Lifecycle) is the temporal anchor.

**CC-5 — No Interpretation Without Observation:** The Epistemic Runtimes (RT-09, RT-10, RT-11) may not produce epistemic products from operations that have not passed through RT-08 (inbound) or been generated by constitutionally authorized internal runtimes. Fabricated epistemic chains are constitutionally void.

**CC-6 — No Action Without Decision:** No Action operation may be submitted to RT-03 without a constitutionally formed Decision (RT-11, requiring RT-09 + RT-10 deliberation). Undecided actions are constitutionally void.

### 2.4 Four Operational States

Every constitutional operation exists in one of four states (derived from D-4):

- **REJECTED:** Operation failed one or more gates; not admitted; no state change to Reality Fabric.
- **ADMITTED:** Operation passed all gates; atomic commit pending.
- **COMMIT FAILED:** Operation passed all gates but fabric admission failed; rollback required.
- **LOST:** Operation state cannot be determined; reconciliation by RT-14 required.

Interactions between runtimes are conditioned on the operational state of relevant operations.

### 2.5 Blocking Classification Definitions

For the interaction catalogue (Part 3), blocking behavior is defined as:

- **BLOCK:** Initiating runtime halts until receiving runtime returns a constitutional result.
- **NON-BLOCK:** Initiating runtime does not halt; receiving runtime processes asynchronously.
- **COND-BLOCK:** Initiating runtime halts only if receiving runtime returns a REJECTED or FAILED result; on success, initiating runtime may proceed without waiting for full completion.
- **GATE-BLOCK:** Specific to RT-03 gate processing; runtime is suspended until RT-03 gates complete; applies to all Class A operations.

## PART 11 — RECURSIVE INTERACTION GRAPH

### 11.1 Constitutionally Permitted Recursion

Recursive interactions are interactions where a runtime's output eventually becomes its own input through a chain of other runtimes. Two types are constitutionally recognized:

**Type R1 — Constitutional Loop Recursion (D8):**  
The full D8 Constitutional Loop is recursive by design:
`Observation → Evidence → Knowledge → Understanding → Deliberation → Decision → Action → Consequence → Observation of Consequence → [new loop]`

This recursion is constitutionally mandatory (CLI-3 — Feedback Completeness). The system must close this loop.

**Type R2 — Deliberation Recursion (D7):**  
RT-11 may request updated CUM from RT-10 during deliberation. RT-10 queries RT-15 for updated DUMs. This is a bounded recursion (deliberation window bounded; not infinite).

### 11.2 Forbidden Recursion

**FR-1:** RT-03 may not gate its own operations. RT-03 is self-validating through its internal gate logic. No recursive RT-03→RT-03 gating.

**FR-2:** RT-04 audit operations may not be gated by RT-03. RT-04 cannot create a recursive audit-of-audit chain that returns to RT-03.

**FR-3:** RT-11 deliberation may not reference a Decision it itself produced as evidence for the same deliberation cycle. Decision D cannot be used as evidence for the deliberation that produced D.

**FR-4:** RT-16 amendment operations may not be initiated by the Amendment Record produced by a concurrent RT-16 operation. No self-amending amendment chain within a single amendment cycle.

### 11.3 The Reality Feedback Loop (Required Recursion)

The D5 Part 8 Reality Feedback Loop is the primary constitutionally required recursive structure:

```
RT-13 (action) → External Reality → RT-14 (consequence) → RT-08 (re-entry) 
  → RT-09 → RT-10 → RT-11 [forms new decision based on consequence]
  → RT-13 (new action if decided) → [loop continues]
```

RT-14 (Reality Feedback Runtime) is constitutionally responsible for closing this loop. Failure to close the loop within the Mandatory Propagation Window is a CLI-3 (Feedback Completeness) violation.

## PART 15 — CONSTITUTIONAL LOOP CYCLE ANALYSIS

### 15.1 Loop Integrity

The D8 Constitutional Loop is constitutionally mandated to be:
- **Non-optional:** Every observation must complete its loop. Observations that do not reach consequence evaluation violate CLI-3.
- **Non-inversible:** The sequence Observation → Deliberation → Action cannot be reversed. Action does not precede Observation in any constitutional cycle.
- **Bounded:** Each loop cycle is bounded by the Mandatory Propagation Window (MPW). Loops that exceed MPW trigger operational suspension.
- **Recursive:** The consequence of one cycle becomes the observation of the next. The system is designed for continuous operation.

### 15.2 Runtime-to-Loop-Phase Mapping

| Deliberation | RT-11 | RT-10, RT-12 |
| Decision | RT-11 | RT-12, RT-03 |
| Action | RT-13 | RT-03, RT-05 |
