## OBSERVATIONS (NON-DEFICIENT)

The following items were examined with particular scrutiny. Each was found to be properly handled and does not constitute a deficiency.

**OBS-01: Naming Conflict (C-1) — "Decision Runtime" vs. "Constitutional Compliance Runtime"**

A0 §3.13 names RT-12 "Decision Runtime." A1 §3.0 and R0 §5.8 RNS-1 name it "Constitutional Compliance Runtime." The specification correctly discloses this as Conflict C-1, resolves it by A0 authority hierarchy, uses "Decision Runtime" throughout, and confines "Constitutional Compliance Runtime" exclusively to conflict disclosure contexts. This is correctly handled. NOT a deficiency.

**OBS-02: Functional Model Conflict (C-2) — A0 decision-formation model vs. A1 compliance-verification model**

A0 §3.13 characterizes RT-12 as forming and owning CivilizationalDecision. A1 §6.1 and PAIR 40 characterize RT-12 as producing Compliance Verification Records and A1 §6.1 assigns "Decision Record" to RT-11. The specification correctly discloses this as Conflict C-2, resolves it by A0 authority, applies A0's decision-formation model throughout, and references the A1 compliance model only in conflict disclosures. This is correctly handled. NOT a deficiency.

**OBS-03: Object Flow Direction Ambiguity (C-3) — RT-12 as submitter vs. RT-03 as initiator**

A0 §3.13 R3 characterizes RT-12 as submitting to RT-03. A1 PAIR 43 characterizes RT-03 as calling RT-12 at Gate 5. A1 §12.3 Step 10 implies RT-11 submits to RT-03. The specification correctly discloses this as Conflict C-3, applies A0's submission model as primary, and characterizes the Gate 5 invocation as a concurrent sub-interaction within the same operation. This is correctly handled. NOT a deficiency.

**OBS-04: PAIR 53 Lacks A0 §3.13 Basis (C-4)**

A1 §3.5 PAIR 53 (RT-15 ↔ RT-12) has no basis in A0 §3.13 Dependencies or Dependents. The specification correctly discloses this as Conflict C-4, documents PAIR 53 from A1 as required, excludes RT-15 from RS-26 and RS-27 as required by A0, and flags the interaction for auditor review. This is correctly handled. NOT a deficiency.

**OBS-05: RT-14 Classification Ambiguity (C-5)**

RT-14 is classified as a Dependent of RT-12 in A0 §3.13 Dependents, yet RT-14 also delivers TerminalStatusRecord to RT-12. The specification correctly discloses this as Conflict C-5, explains both perspectives (RT-14 as Dependent because it depends on RT-12's OAR; RT-14 delivering feedback to RT-12 as a return flow, not a forward dependency), and places RT-14 in RS-27 (Dependents) while documenting TerminalStatusRecord in RS-08 (Inputs). This is correctly handled. NOT a deficiency.

**OBS-06: Authority Type Gap (C-6) — A0 §4.3 silence on RT-12's authority type**

A0 §4.3 identifies RT-12 as the validation point for Decision Authority but does not assign RT-12 a named authority type (AIR-1 through AIR-5). A1 §5.1 fills this gap with AIR-2/Compliance. The specification correctly discloses this as Conflict C-6, uses A1 §5.1 as a lower-authority supplement filling A0's gap, explicitly notes A0 §4.3 does not directly confirm the assignment, and claims no authority beyond AIR-2/Compliance. This is correctly handled. NOT a deficiency.

**OBS-07: RS-31 Decision Phase Primary — RT-11 vs. RT-12**

A1 §15.2 lists RT-11 as Primary in the Decision phase. Under A0's model, one might expect RT-12 to be Primary given its decision formation role. The specification correctly follows A1 §15.2 for loop classification (as mandated by the audit instruction), notes the tension with A0's decision-formation model (related to C-2), and does not invent a Primary role for RT-12. This is correctly handled. NOT a deficiency.
