## 4. Data-Flow Trace

Pre-remediation flow for the strings at lines 154, 156, 189:

1. **LLM system prompt (Anthropic messages.create):** YES — unconditional entry in the `system:` array at every voice request.
2. **HTTP response body:** For line 154/156 — NO direct echo; the `{ ok, reply }` payload is the model's textual output only. BUT the model's output is conditioned on this system prompt, so the tokens can leak indirectly through generated replies. For line 189 — YES, direct: the string `'I was unable to complete that request, sir.'` returns verbatim as `reply` on any failure path.
3. **Gemini / Google APIs:** NO. This route uses only the Anthropic client (`client = getAnthropicClient()`).
4. **Logs / telemetry:** NO. The system prompt is not logged in `routes/voice-chat.js`.
5. **Obsidian:** The reply text is appended to Obsidian only when `req.identity?.role === 'master'` (line 238–246, P0-I3 gate). No leakage to shared vault for Users.
6. **Postgres / database persistence:** The gateway's `storeMemory` calls persist the user's message and the reply text, not the system prompt (line 44 and 192). The reply may echo PII if the model surfaced it.
7. **WebSocket messages / error bodies:** Route is HTTP JSON only. Error paths (line 251–258) return `error?.message`, which does not include the system prompt.

## 5. Reachability Analysis

**Mounting chain (verified in server.js):**
- Line 277: `app.use('/api', ...kernelChain)` — `kernelChain` = [resolveIdentity, resolveOwnership, checkAuthority, checkGovernance].
- Line 287: `app.use("/api/voice-chat", voiceLimiter)` — rate limiter, does not gate identity.
- Line 322–337: `_loadAgentRoutes()` mounts `routes/voice-chat.js` under `/api`. Combined with the file's internal `router.post('/voice-chat', _auth, ...)`, the final path is `POST /api/voice-chat` with `requireAppAccess` as first middleware inside the handler chain.

**Effective identity gates before the string sites:**
1. `requireAppAccess` (route-level `_auth`) — accepts `x-app-key` matching `APP_ACCESS_KEY` OR a valid `apex_token` JWT cookie. Rejects unauthenticated callers with 401.
2. `resolveIdentity` (kernel gate 1) — sets `req.identity.{humanId,role,email,sessionId,authMethod}`. JWT payload `role` maps to `req.identity.role`; legacy tokens default to `'master'`.
3. **NO further role gate exists between line 22 (route entry) and line 154/156.** The `_vcIsMaster` gate at line 78 wraps only `_vcBuildAlexContext` (P0.5).

**Reachability of the hardcoded strings pre-remediation:**
- **Master identity** (`req.identity.role === 'master'`) — YES, reaches strings. Correct.
- **User identity** (`req.identity.role === 'user'`) — YES, reaches strings. WRONG. Strings sent to LLM in User context.
- **Unauthenticated caller** — NO. Blocked at `_auth` (verified by P0 test T-I3).
- **Identity-switching via client-controlled body params** — NO. The role is read from JWT payload server-side (`_decodeApexToken` → `jwtPayload?.role`). No `req.body.role` / `req.query.role` / `req.headers.role` reads anywhere in the file (P0.5 T-2 and P0.6 T-6 confirm this).

**Is P0.5 the only path?** NO. P0.5 gates only the dynamic Obsidian-backed alexContext. The hardcoded persona strings at 154/156/157/189 are a separate, previously ungated code path.

## 6. Threat Model Answers

A. Can a User cause code at 154–156 to execute? **YES** — no role gate between route entry and system-array construction.
B. Can a User receive the hardcoded strings verbatim in HTTP response? **YES (line 189 fallback), NO (lines 154/156 not echoed raw).**
C. Can a User cause the strings to be inserted into an LLM prompt on their behalf? **YES** — Anthropic call sends them in `system`.
D. Can a User indirectly learn PII through LLM output? **YES** — model is conditioned on Master's name, honorific, city, region, and Master's data surface; it can and will use those tokens in generated replies.
E. Can an unauthenticated caller reach the strings? **NO** — `_auth` returns 401 (P0 test T-I3 confirms).
F. Does the route fail closed on missing `req.identity`? **PARTIAL pre-remediation** — the P0.5 helper fails closed; the hardcoded 154/156 strings did NOT. **FULLY YES post-remediation** — `_vcIsMaster = req.identity?.role === 'master'` returns `false` for undefined identity, selecting the neutral (non-PII) branch of both `_vcPersonaLines` and `_vcFallbackReply`.
G. Dead code? **NO** — the `while (loopCount < maxLoops)` block always runs when `finalReply === ''` (initial state), and the system array is rebuilt every iteration.

## 7. Decision Gate

**CONFIRMED EXPOSURE.**

The P0.5 Master-only gate only wrapped the dynamic Obsidian identity + Layer-9 facts. The static hardcoded persona strings and fallback reply were outside any identity gate and reached the LLM system prompt (and, for line 189, the HTTP response body) for any authenticated non-Master caller.

## 8. Remediation Performed

**Option B (consolidation).** Added a Master-only persona helper alongside `_vcBuildAlexContext`, gated on the same server-resolved `_vcIsMaster` flag. Non-Master callers receive a neutral persona that omits given name, city, region, honorific, and health-data surface, while preserving system/product persona (VOICE RULES, "direct, confident, and loyal", current date) and the tool-use behavioural instructions.

**Diff footprint in `routes/voice-chat.js`:**

1. After `_vcBuildAlexContext` declaration (lines 80–94 post-fix): introduce
   - `_vcTodayStr` — factored out of the previous inline `toLocaleDateString`.
   - `_vcPersonaLines` — a `_vcIsMaster ? [masterLine1, masterLine2] : [neutralLine1, neutralLine2]` array. Master branch preserves the exact original strings (Master behaviour unchanged); neutral branch omits PII and Master-only assertions.
   - `_vcFallbackReply` — `_vcIsMaster ? 'I was unable to complete that request, sir.' : 'I was unable to complete that request.'`.
2. In the `system:` array (lines 169, 171 post-fix): replace the two raw template strings with `_vcPersonaLines[0]` and `_vcPersonaLines[1]`.
3. Line 204 post-fix: replace `finalReply = 'I was unable to complete that request, sir.'` with `finalReply = _vcFallbackReply`.

**Rules honoured:**
- Identity source is `req.identity.role` (server-resolved from JWT); no client-controlled reads.
- Fails closed: `req.identity?.role === 'master'` yields `false` for undefined identity, selecting the neutral branch.
- No new middleware, tables, or architecture.
- Master behaviour preserved verbatim (T-2b confirms all PII tokens still present in the Master branch).
